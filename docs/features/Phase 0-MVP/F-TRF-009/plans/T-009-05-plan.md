# T-009-05 Implementation Plan

TASK: T-009-05 My Files screen at `/files` in wa.web — list, filter pills, cursor paging (FR-009-1/2/4/5, AC-009-1 client half, EC-009-4)

GOAL: Build the **My Files** screen at `/files` (UI-Reference §5.4) in `wa.web`. A signed-in-only route that renders endpoint 14's (`GET /api/v1/transfers`, TA-4.2#14 — already shipped T-009-01/T-009-02, NO .NET diff for this task) cursor-paged transfer history: header "My Files" + **New transfer** primary (→ `/`); filter pills **All / Active / Expired** (active pill `--accent-soft` per spec); rows per FR-009-1 (name truncated with `title`, file count, total size via the existing TA-8.5 1024-based `formatBytes` at `src/wa.web/src/core/upload/formatBytes.ts`, recipient count with "Link only" when 0 — EC-009-4, status chip text + color not color-only (F-TRF-016), expiry countdown ticking client-side from ExpiresAtUtc — no per-second server calls — and "Expired {date}" when past — AC-009-3, downloads "87/100"); **Prev / Next** cursor paging driven by the endpoint's `nextCursor` (TA-4.1.4, default page 25); empty state FR-009-5 (icon + "No transfers yet." + CTA "Send something" → `/`). Sort is fixed `CreatedAtUtc DESC` — no user re-sort in MVP. The pills MUST match the server's canonical `?status=all|active|expired` semantics exactly (US-009-02): all = everything not physically gone, active = Status=1, expired = Status IN (2,3) including download-limit — i.e. the client just forwards the pill's wire value, never re-filters rows client-side.
