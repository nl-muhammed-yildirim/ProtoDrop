# T-009-02 Implementation Plan

TASK: T-009-02 Status filter on endpoint 14 (All / Active / Expired)

GOAL: Add an optional ?status= filter to endpoint 14 (ListMyTransfersQuery) — all (default, everything not physically gone), active = Status=1, expired = Status IN (2,3) — composing with the cursor and returning 400 VALIDATION naming the allowed values for anything unknown.

## Design
- **Wire form** (TA-4.1.4 + TA-4.2#14): endpoint 14 already binds ?cursor=&limit=; add ?status=all|active|expired (case-insensitive, default all). T-009-01 precedent: raw query params are validated at the **endpoint** (`Program.cs`, limit block) and a *resolved primitive* is threaded into the MediatR record. Status follows that idiom — endpoint parses + validates; handler passes through; store owns the predicate.
- **Resolved primitive, not a new enum**: endpoint resolves ?status= to a nullable byte set — all/absent → null (no constraint), active → {1}, expired → {2,3}. This mirrors how limit is a plain `int` on the record (T-009-01). No new domain type; the closed set becomes {null, {1}, {2,3}}.
- **Store contract**: additive optional last param `IReadOnlyCollection<byte>? statuses` on ITransferStore.ListByOwnerAsync (`src/wa.application/UseCases/Transfers/ITransferStore.cs`). Null = no status filter (All). Because the signature changes, ALL five implementers must update or the build breaks — the EF adapter plus the test stubs (rows 4–7 of FILES FOR CODER); only the EF one and ListMyTransfersTests' stub change behavior, the other three are signature-only.
- **Predicate composition**: within a fixed owner + status set the keyset cursor (created_at desc, id desc) plus the status predicate yields page 2 of active that stays inside the active set only — no re-scan. Staleness rule from US-009-02: a transfer expiring while the list is open stays in Active until next render (acceptable).
- **Deleted rows**: stay out of every filter via the unchanged `DeletedAtUtc == null` guard — "all" needs no extra predicate (FR-009-4: deleted rows disappear from the list; chip mapping Active=1 / Expired=IN(2,3) is now the closed set). No new index: IX_Transfer_Owner + the expiry index cover owner-scoped status predicates at MVP scale.

## TESTS
All xUnit facts go into `tests/wa.application.unit/Transfers/ListMyTransfersTests.cs` (hand-stub store, no Moq/EF — T-008-06 / T-009-01 style). AC coverage:
- **US-009-02 gherkin** (5 active + 4 expired transfers): seed 5 rows Status=1 and a mix of the rest as Status=2 and Status=3 (both present), all owner-owned, distinct created times.
  - ListMyTransfersTests.Filter_Active_ReturnsOnlyStatus1 → exactly the 5 active.
  - ListMyTransfersTests.Filter_Expired_ReturnsStatus2And3 → exactly those 4 expired-or-download-limit rows.
  - ListMyTransfersTests.Filter_AllOrOmitted_ReturnsAllMostRecentFirst → all 9, most recent first (covers both ?status=all and omitted default).
- **US-009-02 edge case** (filter + cursor compose): seed more than 25 active with expired rows interleaved; page 1 ?status=active then follow the returned cursor.
  - ListMyTransfersTests.Filter_And_Cursor_Page2_StaysWithinActiveSet → page 2 returns only Status=1 rows, no dupes/gaps (proves composition within the filtered set).
- **Unknown status value → 400 VALIDATION**: endpoint-level parse in Program.cs (same house idiom as T-009-01's limit validation — not unit-covered there either), so it lands via the same pattern; a single fact under tests/wa.api.integration on the existing Testcontainers stack is optional wire proof, not required by this task's exit check.

## LIMITS & CONSTANTS CITED
- page-size = 25 (limit default 25, reject <= 0 or > 25 with 400 VALIDATION) — pinned in T-009-01 code (`Program.cs` limit block); confirmed there, not re-invented. Not a Part 2 Limits Registry constant.
- status values all / active / expired → raw Status bytes null / {1} / {2,3} — US-009-02 Technical notes + FR-009-4 (status chip mapping).

## ERROR CODES
- VALIDATION: unknown ?status= value (not one of all / active / expired) — 400, detail names the allowed values. **Existing** member; no new ProblemCode added (closed list unchanged).
- UNAUTHENTICATED: missing owner session key — unchanged from T-009-01.

## MIGRATIONS
none (no schema change — Status column + DeletedAtUtc already exist).

## ASSUMPTIONS
- Raw query-param validation (limit, now status) lives in the endpoint per T-009-01 precedent; the handler receives a resolved primitive and does no string parsing — Program.cs stays thin, unit tests cover mapping + predicate.
- The query record's new field is a nullable `IReadOnlyCollection<byte>?` byte set (not a new domain enum) to stay consistent with T-009-01's primitive-threading convention.
- Case-insensitive wire matching (active / Active both accepted).
- "All / everything not physically gone" = owner scope + DeletedAtUtc == null only; deleted rows are excluded from every filter by that existing guard alone (no extra predicate for all).
