# T-009-06 — Delete confirm modal + row actions (copy / view / re-send)

**Spec:** `US-009-04-delete/T-009-06-delete-confirm-ui.md` | **Stories:** US-009-04 (+ US-009-01 row actions)
**Cites:** FR-009-3, AC-009-2 (client half), EC-009-2 | **Milestone task:** T-022 part 6/6 — LAST task of F-TRF-009.

## Context (grounded from live source at cfefc8a+ chain, branch feature/F-TRF-009)

The My Files screen (`FilesPage.tsx`, shipped T-009-05 / commit 83b7bef) already renders rows with
`mf-*` markup and fetches `GET /api/v1/transfers?cursor=&status=` with `credentials:'include'`. This task adds:

1. **Row actions** — four ghost buttons per row (UI-Reference §5.4): **Copy link**, **View**, **Re-send**, **Delete**.
2. **Delete confirm modal** (UI-Reference §4.5, danger button) whose copy names exactly what's going away:
   `Delete transfer? {fileCount} files, {formatBytes(totalBytes)}. This can't be undone.` — count + size FROM THE ROW DATA (AC-009-2).
3. **Confirm →** `DELETE /api/v1/transfers/{id}` (`credentials:'include'`). Success = **`204 NoContent` OR 404 with problem body `code === 'NOT_FOUND'`** (EC-009-2: second tab deleting the same transfer — no error toast, row quietly vanishes). Then remove the row locally + inline toast `Transfer deleted.` with `role=status`.
4. **Cancel →** nothing sent; row unchanged.

## Architectural decisions (all grounded)

### D1 — linkId is missing from the row wire: minimal 6-file .NET diff

`/t/{linkId}` needs an 8-char Crockford base32 value (`wa.domain/ValueObjects/LinkId.cs`: `Length = 8`,
charset `"0123456789abcdefghjkmnpqrstvwxyz"` — **lowercase only**; minted at finalize, NOT derivable from the Guid 'n'-form).
`MyTransferRow` (`ListMyTransfers.cs:10-19`) carries 9 fields — no linkId. Endpoint-15 detail (Program.cs:657-685) also omits it.

→ Add `LinkId: string` as the **10th positional field** on `MyTransferRow`, projected in
`TransferStore.ListByOwnerAsync` LINQ (the anonymous projection at :47 already selects from the full entity — add
`LinkId = t.LinkId`), passed through both record-construction sites (:71, :114), and added to BOTH endpoint wire objects
in Program.cs: endpoint-14 rows (anon object in `items = result.Items.Select(...)`, after `recipientCount`) as
`linkId = r.LinkId` **and** endpoint-15 detail body (after `recipientCount = result.Row.RecipientCount,`) as
`linkId = result.Row.LinkId`. TS DTO (`formatting.ts:9` `MyTransferRowDto`) gets `linkId: string` as 10th field.

This keeps Copy/View purely client-side with **no extra round-trip** (AC-009-1 — no per-row server calls).
The additive wire field is backwards-compatible: FilesPage consumes named fields only; unit tests construct the record
positionally so tsc/csc force every construction site to update (that's the safety net).

### D2 — Confirm copy must pin REAL formatBytes output, not the doc number

`formatBytes.ts:1-17` (`TA-8.5`, 1024-based): `value < 10 ? toFixed(2) : toFixed(1)` + unit name.
**Verified:** `formatBytes(1_288_490_188)` → `"1.20 GB"` (1.1999… ≥ 10 after division? No — 1.1999 < 10 → toFixed(2)).
The spec's "1.2 GB" is illustrative; the row and modal both render through `formatBytes`, so they match by construction.
**Tests must assert `"Delete transfer? 3 files, 1.20 GB."` for a fixture row with fileCount=3 / totalBytes=1_288_490_188.**

### D3 — EC-009-2 success predicate (client)

Endpoint 17 returns **`204 NoContent`** (Program.cs:698, no body) or **404 + `ProblemWriter.Build(...)` body**.
The problem wire shape is `{ code, title, status }` — `code === 'NOT_FOUND'` for endpoint-17 404s
(ProblemCodes.NotFound literal; ProblemWriter.cs). Client predicate:

```ts
const ok = res.status === 204 || (res.status === 404 && parsedBody?.code === 'NOT_FOUND');
```

Parse the body defensively (`await res.json().catch(() => null)`) — a bare 404 without code is NOT success.

### D4 — Row action buttons + wiring

- Markup: an actions cell (`.mf-actions` flex child, new class in index.css) appended INSIDE each existing
  `.mf-row`, rendering four `<button type="button" className="au-ghost-btn">` (reuse the EXISTING ghost button class; no new base style). Each needs `aria-label` for screen-reader parity (F-TRF-016: text + icon, not color-only — here labels carry meaning).
- **Copy link:** `navigator.clipboard.writeText(\`${window.location.origin}/t/${row.linkId}\`)` with the execCommand fallback pattern from `LinkScreen.tsx:68` (clipboard API precedent). The recipient URL form `{origin}/t/{linkId}` is pinned by LinkId.cs doc comment ("rendered into {origin}/t/{linkId}").
- **View:** call window.open with the transfer URL, target `_blank` and feature string `noopener` — RecipientPage is a guest route (App.tsx branch), no auth needed. No existing window.open precedent in wa.web; this is the architect's decision for "new context" per spec line 25/39.
- **Re-send:** ghost button with link icon, **route stub only** — onClick shows an inline `role=status` toast `Re-send lands in T-023 (F-TRF-010).` and sends NOTHING. The endpoint (`POST /api/v1/transfers/{id}/resend`) ships in F-TRF-010's T-023; spec line 39: "route stub only for now". Cite T-023 in a comment at the handler.
- **Delete:** opens the confirm modal (local state in FilesPage — it already owns rows).

### D5 — Modal (mirror DangerZone.tsx exactly)

Backdrop + Escape key handler + Cancel button + Confirm **danger** button (`pf-modal-*` CSS block, index.css:867-965 is
the template — reuse `.pf-modal-backdrop / .pf-modal / .pf-modal-title / .pf-modal-copy / .pf-modal-actions /
.pf-modal-cancel / .pf-modal-confirm` as-is; NO new modal classes needed). Awaited DELETE with `credentials:'include'`;
success → close modal + remove row locally (state update in FilesPage); failure (non-EC-009-2) → inline
`role=alert` error inside the modal, modal stays open. Confirm disabled while awaiting (double-click guard — the
DangerZone pattern).

### D6 — Toast: FilesPage-owned inline region (NOT App's deleteToast)

App.tsx's `deleteToast` is DropZone-scoped (T-008-09 precedent, passed as a prop to DropZone only). For My Files,
FilesPage renders its own `<div role="status">` with a 5 s auto-dismiss timer (`window.setTimeout`, cleared on unmount) — same shape as DangerZone's inline status region. No App.tsx prop plumbing needed.

`// @vitest-environment jsdom`; in-memory localStorage shim; `writeSession` THEN pushState + PopStateEvent BEFORE
createRoot; `vi.stubGlobal('fetch', fetchSpy)` capture-closure. New facts for the T-009-06 suite (in FilesPage.test.tsx):

2. View → stubbed window.open called with `/t/{fixtureLinkId}`, `_blank`, noopener.
3. Re-send button present + onClick produces the T-023 status toast and NO fetch call.
4. Delete modal copy: fixture row fileCount=3 / totalBytes=1_288_490_188 → text exactly `Delete transfer? 3 files, 1.20 GB. This can't be undone.` (D2).
5. Confirm (fetch 204) → fetch called with method DELETE + credentials include → row removed from DOM + toast `Transfer deleted.` (`role=status`).
6. Confirm (fetch 404 + body `{code:'NOT_FOUND'}`) → same as success: row gone, **no** error region (EC-009-2).
7. Confirm (fetch 500 or 404-without-code) → inline `role=alert` error shown, modal stays open.
8. Cancel / Escape → no fetch call; row unchanged.
