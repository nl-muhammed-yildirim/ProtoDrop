# T-010-01 Implementation Plan

TASK: T-010-01 ResendTransferCommand + endpoint 16 — new draft sharing blobs (FR-010-1/2/3, AC-010-1)

GOAL: POST /api/v1/transfers/{id}/resend (endpoint 16, cookie required) creates a new DRAFT transfer (Status=0) that shares the original's blobs via the existing BlobRef/FileItem junction — new LinkId (fresh 8-char Crockford, no reuse), fresh expiry and download count, RefCount++ per shared blob (no data copy, ADR-009) — pre-filled as a snapshot of the original (recipient emails, password hash, note, sender), with SupersededBy set on the original when the draft is later sent through the existing send path. AC-010-1 holds server-side; the FILES_GONE predicate + rollback are T-010-02's scope and must slot in cleanly (single transaction requirement below).

## ERROR CODES

- FORBIDDEN (403): guest original only (OwnerAppUserId null, EC-010-4) — first usage of ProblemCodes.Forbidden in the codebase; no new members added by this task (FILES_GONE arrives with T-010-02).
- NOT_FOUND (404): unknown transfer id or Status=4 row — existing member.

## ASSUMPTIONS

- No new packages, no new ProblemCodes members, no telemetry event names added (transfer.created is emitted by the existing send path — EventType wire name, not a TelemetryEvents member).
- FileItem.Id on re-send: FRESH Guids (the task spec's "new FileItem rows" language), BlobRefId copied from the original row. This is where T-010-02 or the flagged blob-path follow-up may force reuse of original fileIds — both outcomes stay inside one transaction either way.
- Owner-scope mapping pinned by the task file: GUEST row (OwnerAppUserId null) → FORBIDDEN via ResendForbiddenException (EC-010-4); FOREIGN owner row (non-null, != session user) → NOT_FOUND (null result). Both satisfy no-enumeration; NOT_FOUND is also used for unknown id / Status=4 rows.
- EmailRecipient rows are the draft's pending editable state: created on re-send from the original's addresses; T-010-03 reads them back via a query (that read surface is T-010-03's scope — this task only creates the rows and returns them in endpoint 16's JSON).
- Re-send of an ACTIVE transfer is allowed (two live links, same files) — no status restriction beyond excluding Status=4.
