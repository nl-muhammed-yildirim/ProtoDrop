TASK: T-010-02 FILES_GONE predicate + re-send draft cleanup (FR-010-4, AC-010-2, EC-010-2)

GOAL: one shared blob-existence gate — "the transfer's files are physically gone" — applied at BOTH creation time (step 0 inside SaveResendAsync's transaction, before any insert or RefCount bump) and send time (inside SaveSendAsync for re-send drafts only), throwing a new sealed FilesGoneException that endpoint 16 (/resend) and /send catch and map to BusinessException(ProblemCodes.FilesGone) → Problem+JSON 410. ## ASSUMPTIONS

- The sealed FilesGoneException lives at application level in SendTransfer.cs (row 2) — same pattern as ResendForbiddenException; caught by Program.cs endpoints, not by middleware. No handler needs IBlobStore injected: the gate is private to SendStore (Design B), which already owns both transaction methods and now holds IBlobStore directly.
- Exit check c wins over instruction 1's literal wording ("PhysicallyDeletedAtUtc IS NULL AND blob head OK"): the exit check explicitly says the gate checks physical deletion, not the buffer flag alone. The predicate therefore reads NO column flags — only row presence + ExistsAsync. If T-005-03 semantics ever change to keep rows after f-delete-blobs, only the missing-row branch of the predicate needs revisiting (flag as DECISION then).
- A missing BlobRef row = gone: T-005-03's job removes blob and row in one pass (swallowing BlobNotFound on the storage side), so at gate time the two checks are equivalent; the row check exists because a gone blob has no path to ask about.
- The send-time gate is scoped to re-send drafts only (transfer.SourcedFrom set). A normal draft's blobs cannot be "gone" via this lifecycle (their finalize would have failed instead) — keeping the gate off the normal /send path avoids adding an IBlobStore round-trip to every normal send and keeps existing SendTransferHandlerTests green.
- The create-time gate runs inside SaveResendAsync's transaction as step 0 (before inserts) rather than before the handler builds rows — both positions yield identical AC-010-2 behavior; inside the transaction is where T-010-01's plan pinned the insertion point ("T-010-02 inserts its FILES_GONE gate at step 0 inside this same transaction").
- No new packages (xUnit + hand stubs only), no telemetry event names added, no CSS/storage-key surface touched.
