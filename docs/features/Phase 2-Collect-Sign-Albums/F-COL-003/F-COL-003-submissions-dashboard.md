# F-COL-003 — Submissions Dashboard

**Priority:** P1 (Phase 2a) | **Phase:** 2a — Collect
**Spec source:** `02-feature-plan.md` F-COL-003 (outline → remapped below as FR-027-*) | **Architecture:** TA-3.2, TA-4.2, TA-6.6
**Milestone tasks:** T-044 (M5)

---

## Description

The collector's cockpit for one collection: **every submission in one list** — person, files, size, status, when — with per-person **Download all** (a zip of that person's submission, generated by the same `f-zip` function as transfers, scoped to the entry) and status actions (accepted / declined / done — F-COL-005). Search finds a specific person by name or email.

**Actors:** collector (owner), operator.
**Value:** the "one" in "many → one" — the collector never opens 47 emails to chase files.

## Functional requirements

| ID | Requirement |
|---|---|
| FR-027-1 | Dashboard screen (`/collections/{id}`): all submissions, newest first — sender name (or "Anonymous"), email (if given), file count, total size, status chip, submit time. |
| FR-027-2 | Per-person **Download all**: zips that entry's files with original names (`f-zip` extension, blob path `collections/{cid}/entries/{eid}/all.zip`, 202-while-generating pattern exactly as F-TRF-004). |
| FR-027-3 | Status actions per entry: **Accepted**, **Declined** (F-COL-005), **Done** (F-COL-005). Status chips: green (done), blue (accepted), gray (received), amber (declined) — color never the only signal (F-TRF-016: text present). |
| FR-027-4 | Search: by sender name (partial, case-insensitive) or email (exact or partial). Combined with status filter (All / Received / Accepted / Declined / Done). |
| FR-027-5 | Cursor pagination (TA-4.1.4) — collections can hold 200 entries (FR-025-5). |
| FR-027-6 | Single-file downloads per entry (SAS 30 min, TA-3.6) alongside the zip action. |

## Acceptance criteria

```gherkin
AC-027-1: A collector with 3 submissions opens the dashboard
  Then all 3 entries are listed with person, size, status, and time

AC-027-2: The collector clicks Download all on an entry
  Then a zip of exactly that entry's files is delivered (202 while generating, then the file)

AC-027-3: The collector searches "maria"
  Then only entries whose name or email matches are shown

AC-027-4: The collector marks an entry Declined
  Then the chip updates and the action is available in the audit-free flow (no confirm modal for Decline; Done/Decline are reversible while not Done)
```

## Edge cases

| ID | Case | Behavior |
|---|---|---|
| EC-027-1 | Entry with a 0-byte or single file | Zip action available even for one file (consistent naming); no "download all" hidden for 1 file here (unlike transfers — collector workflow, documented) |
| EC-027-2 | Download-all while a new submission is adding files | Zip is a snapshot of the entry at generation time; new entries are separate rows (never live-editable) |
| EC-027-3 | Declined entry re-accepted | Allowed until marked **Done**; Done is terminal (F-COL-005) |
| EC-027-4 | Owner's account deleted | Dashboard accessible to the re-homed collection only via the re-homed owner (F-COL-001 EC-025-2) |

## UI notes (UI-Reference §4.7, §5.4)

- Admin-table pattern (4.7) but lighter: filter bar (search + status select), sticky header, rows with status chips, row actions as ghost buttons (**Zip**, **Decline**, **Done**, **Accepted** as applicable).
- Confirm modal only for **Done** ("Mark as done? The contributor will be notified.") — Decline/Accept are reversible (no modal).
- Empty state: icon + "No submissions yet." + **Copy link** shortcut (share the collection link, F-COL-001).
- Counters above the list: "3 of 12 received" style only if the collector set an expected count (proposed, D-21 — off by default: show raw count "12 submissions").

## Technical notes

- Endpoints (TA-4.2 extension, ADR note): `GET /api/v1/collections/{id}/entries?q=&status=&cursor=` (30), `PATCH /api/v1/collections/{id}/entries/{entryId}` (31, status), `GET /api/v1/collections/{id}/entries/{entryId}/files/{fileId}/download-url` (32), `GET /api/v1/collections/{id}/entries/{entryId}/download-all-url` (33).
- MediatR: `ListEntriesQuery`, `SetEntryStatusCommand`, `GetEntryDownloadUrlQuery`, `GetEntryZipUrlQuery`.
- `f-zip` extension (TA-6.6): source scope `collections/{cid}/entries/{eid}/files/*`; same cap logic (`MAX_ZIP_SIZE`), same de-dup (`_1`/`_2`), same 202 polling.
- Events (TA-5.3 extension): `collection.entry.status_changed { collectionId, entryId, from, to }`.
- Telemetry (TA-10.2 extension): `collection_status_changed`.

## Test plan

- Unit: search predicate (name partial / email partial); status transition rules (received→accepted/declined; done terminal); cursor paging.
- Integration: AC-027-1…027-4; zip of an entry contains exactly its files (AC-027-2); status transitions audit-free but event-emitted.
- E2E: dashboard with 3 seeded entries → search, zip download, Decline/Accept/Done cycle.
