## 1. Goal

Prove end-to-end, through real code: the API's transfer.created event feeds the real f-email handler, the `Wa:Email:Sender=log` switch picks the log sender, which logs exactly one fully rendered email per address that is not skipped, and an unsubscribe link taken from a rendered email mutes that sender only. **Exit check:** the new integration class `EmailLogSenderE2ETests` (2 facts) and the new unit facts are green, and the rendered HTML is written out as a manual visual-check artifact. Exit item 3 (the 1k burst) is held by the DECISION in §5.

## 2. Design & Decisions

### Grounding facts (they decide the shape of the test)
- **Only the Functions host consumes events.** `src/wa.workers/EmailFunction.cs:42-44` is a `[ServiceBusTrigger("core","email")]`. With `Wa:ServiceBus:ConnectionString` unset, the API registers `InMemoryEventPublisher` (`src/wa.api/Program.cs:42-45`), and nothing consumes it. So on a local dev stack (`npm run dev` + API) no email handler ever runs. A Playwright spec cannot see an email, and faking a consumer in wa.web would prove nothing.
- **The real switch key is `Wa:Email:Sender`, value exactly `"log"`.** It is read with `Environment.GetEnvironmentVariable` in `src/wa.workers/Program.cs:99-106`, inline top-level code that cannot be tested today.
- **Blocking defect: rendered emails have no unsubscribe link.** All 8 transfer HTML templates contain `href="#"` (for example `src/wa.workers/Emails/templates/transfer/en.html:43`). `TemplateData` has no unsubscribe field (`src/wa.application/Ports/ITemplateRenderer.cs:7-11`). `UnsubscribeToken.Create` (`src/wa.application/UseCases/Transfers/UnsubscribeToken.cs:14`) is only called from tests. FR-006-2 requires the footer link, and exit item 2 ("link from a rendered email") cannot pass without it. Wiring it in is the minimum fix that makes the exit check honest. It is not scope creep, because the token format, key (`Wa:Jwt:Secret`) and endpoint were all fixed by T-006-03 (`src/wa.api/Program.cs:132-136`, `:478`).
- `EmailStore.GetSuppressedAddressesAsync` already filters on (address, sender) (`src/wa.infrastructure/Persistence/EmailStore.cs:48-62`), and the handler skips suppressed addresses (`src/wa.application/UseCases/Transfers/SendNotificationEmails.cs:116-120`).

### D-1: Test layer is a .NET integration test, not Playwright
New class `tests/wa.api.integration/Events/EmailLogSenderE2ETests.cs` (TA-14.3 pattern copied from `tests/wa.api.integration/Events/DegradedEmailSeamTests.cs:33-63`):
1. Real API (`WebApplicationFactory<Program>`) on Testcontainers SQL + Azurite, with the Service Bus connection string **cleared**, so DI picks `InMemoryEventPublisher` (TA-0.2 rule 7). Draft, finalize and send run over HTTP.
2. The test reads the real transfer.created envelope that the API published (`InMemoryEventPublisher.GetByTopic`, `src/wa.infrastructure/Events/InMemoryEventPublisher.cs:38-42`) and deserializes it with plain `JsonSerializer`, the same way `src/wa.workers/EmailFunction.cs:48-49` does.
3. The test hands that envelope to a `SendNotificationEmailsHandler` composed exactly like `src/wa.workers/Program.cs:89-117`: real `EmailStore` on its own `WaDbContext` (a separate process in production), real `StubbleTemplateRenderer` with the real templates, and the sender returned by the **same selector code the workers use** for `"log"` (D-2). Only the Service Bus hop is skipped, and `EmailFunction.Run` would add nothing to that hop except an envelope deserialize.
4. Assertions read the log sender's own output (`src/wa.infrastructure/Email/LogEmailSender.cs:18-25`) through a hand-rolled `ILoggerProvider`, and read the DB through a fresh test context.

Why not Playwright: no consumer runs in the local stack, and the unsubscribe page (`src/wa.web/src/features/unsubscribe/UnsubscribePage.tsx:19`) only calls `GET /unsubscribe/{token}`, which this test calls directly. A browser adds no evidence here. Why not wa.workers.unit: it has no SQL container, so suppression could not be proven against the real unique constraint and real query.

### D-2: Extract the sender switch into `EmailSenderSelector` (wa.infrastructure/Email)
`public static IEmailSender Create(string? senderSwitch, string fromAddress, ILoggerFactory loggerFactory)`. It keeps today's exact semantics: ordinal `== "log"` returns `LogEmailSender`, and anything else returns `CommunicationHubEmailSender`. `src/wa.workers/Program.cs:99-106` calls it inside the same lazy `AddSingleton` factory. This makes exit item "dev: log-only sender switch visible" testable without booting a Functions host. It is a deep, tiny module: one decision in one place. Rejected alternative: constructing `LogEmailSender` directly in the test, which would prove the class but not the switch.

### D-3: Per-recipient unsubscribe URL
- `TemplateData` gets a trailing optional positional member `string? UnsubscribeUrl = null`. Existing callers (`tests/wa.workers.unit/Email/StubbleTemplateRendererTests.cs:146-150`, the handler) still compile.
- The handler (application layer, same namespace as `UnsubscribeToken`, so onion-clean) builds `{Wa:Url:Public}/unsubscribe/{UnsubscribeToken.Create(address, senderEmail, UTF8(Wa:Jwt:Secret))}` for each recipient using `templateData with { UnsubscribeUrl = … }`. It returns **null** when `SenderEmail` is null or empty (suppression is keyed on the sender, and `UnsubscribeToken.Verify` rejects an empty sender, `UnsubscribeToken.cs:46-47`) or when the secret is missing (no throw, existing unit fixtures have no secret). The key bytes match the API's verifier (`src/wa.api/Program.cs:135`). The workers already receive `Wa:Jwt:Secret` (`src/wa.workers/Program.cs:47`), so there is **no new env var**.
- The SPA route is `/unsubscribe/(.+)` (`src/wa.web/src/features/unsubscribe/unsubscribeRoute.ts:6`), so the link targets the public origin and the SPA calls the API.
- Renderer: `TemplateRenderModel` gets `UnsubscribeUrl` plus `bool HasUnsubscribeUrl`. Templates wrap the footer paragraph in `{{#HasUnsubscribeUrl}}…{{/HasUnsubscribeUrl}}` with `href="{{UnsubscribeUrl}}"`. A bool section is used rather than a string section to avoid Stubble's string-section semantics. Localized link text stays as is. `.txt` templates are unchanged (Open Question 3).

### D-4: Artifact
The first fact writes the rendered English HTML to `{AppContext.BaseDirectory}/artifacts/T-006-05/transfer-email-en.html` (under `bin/`, which is gitignored: `.gitignore:6`) and prints the path through `ITestOutputHelper`. This is the manual visual check (600 px, dark-mode-safe, calm tone). It is never committed.

### Constraints honored
No new package (LoggerFactory and ConfigurationBuilder come from the shared framework that the integration project already gets through wa.api). No new ProblemCode (18 stay 18), no new telemetry name, no schema change, no new env var, no limit literal (the test derives expiry days from the DB `ExpiresAtUtc`).

```csharp
private async Task RunWorkerAsync(EventEnvelope envelope)
{
    var config = new ConfigurationBuilder().AddInMemoryCollection(new Dictionary<string, string?>
    {
        ["Wa:Url:Public"] = PublicOrigin,
        ["Wa:Jwt:Secret"] = TestSecret,
        ["Wa:Email:FromAddress"] = "no-reply@example.com"
    }).Build();
    await using var workerDb = new WaDbContext(new DbContextOptionsBuilder<WaDbContext>().UseSqlServer(_connString).Options);
    var telemetry = new WaTelemetryReporter(_loggerFactory.CreateLogger<WaTelemetryReporter>(), Encoding.UTF8.GetBytes(TestSecret));
    var handler = new SendNotificationEmailsHandler(
        new EmailStore(workerDb),
        EmailSenderSelector.Create("log", "no-reply@example.com", _loggerFactory), // the Wa:Email:Sender=log arm
        new StubbleTemplateRenderer(_loggerFactory.CreateLogger<StubbleTemplateRenderer>(), telemetry),
        new InMemoryEventPublisher(), // worker-side email_sent sink; not asserted
        new EventDeduplicator(() => DateTimeOffset.UtcNow),
        telemetry,
        config,
        _loggerFactory.CreateLogger<SendNotificationEmailsHandler>());
    await handler.HandleAsync(envelope, 1, 5, CancellationToken.None);
}
```
`_loggerFactory = new LoggerFactory(new ILoggerProvider[] { _capture });` is created in the constructor and disposed in `DisposeAsync`.

## 4. Risks

1. **Env-var bleed.** Several classes set a dummy `Wa__ServiceBus__ConnectionString` and never clear it (`tests/wa.api.integration/SendEndpointTests.cs:45`, `tests/wa.api.integration/Events/DegradedEmailSeamTests.cs:45`). The new class must null it before the host is built. The `Assert.IsType<InMemoryEventPublisher>` guard turns a regression into a clear failure.
2. **Guest recipient cap.** 3 recipients must be ≤ the guest `MaxEmails` (Free: 20 per EC-006-1). If send returns 400, read the seeded plan, and do not lower the recipient count silently.
3. **Template link in the integration output.** If the `Content` link misses, `StubbleTemplateRenderer` loads nothing and throws on `_templates["en"]`. Step 5's first run surfaces this immediately.
