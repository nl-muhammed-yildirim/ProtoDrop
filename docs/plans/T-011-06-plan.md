## ASSUMPTIONS / DECISION
- DECISION: ordering = CreatedAtUtc DESC then Id DESC — mirrors ListByOwnerAsync/SearchTransfersStore and matches CursorCodec's pinned format (base64 of createdAtUtc+id); Email ASC would need a different cursor shape. Documented so review knows the walk order is newest-first, not alphabetical.
- DECISION: soft-deleted users (DeletedAtUtc != null) ARE included — admin screens need to see deleted accounts for force-delete / re-registration (US-011-03 Alternative flows); P0 adds no status indicator column (the screen's force-delete action in T-011-07 will surface it).
- DECISION: q semantics = email substring LIKE %q% — handler trims + lowercases before the store call; AppUser.Email is stored lowercased so a plain Contains on the normalized term matches case-insensitively (CI collation makes the comparison itself case-insensitive, but the stored-lowercase column means an uppercase q would miss without normalization).
- DECISION: per-row computed columns = scalar subqueries inside the EF projection (EF translates to correlated subselects — bounded per row at Take(25)), NOT a loop after fetching rows calling the existing 3-step expression per user (N+1 but each query bounded). Subquery approach keeps ONE bounded query total, mirroring ListByOrderAsync's RecipientCount idiom; the coder must verify EF translates the nested (a)/(b)/(c) storage subquery and fall back to the N+1 loop if translation fails.
- DECISION: storage used uses T-010-04's exact expression (Status IN (1,3)) since the task doc cites US-010-03 per-ref counting; active transfer count follows the task file literally (Status=1 only). Both choices documented so review does not flag the mismatch.
- DECISION: plan name via scalar subquery (FirstOrDefault) — Plans are seeded and never deleted, so null is unexpected but handled: AdminUserRow.PlanName is string? and a null plan renders as null in the JSON (no crash).
- DECISION: handler stays pure (no EF) for unit-testability from wa.application.unit — mirrors SearchTransfersQuery's shape (T-011-04); predicate composition + subqueries sit in the EF query (infrastructure), verified manually.
