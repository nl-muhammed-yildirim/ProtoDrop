**Task row:** `docs/features/Phase 0-MVP/F-TRF-012/F-TRF-012-telemetry.md:88` (US-012-01, gap task 2026-11-17, found in the T-012-06 review; no story task file).

## 1. Goal

No log line written by the API pipeline carries PII through a neutrally named slot (`{Message}`, `{Path}`, `{RequestPath}`): business-error logs carry only code + status, and every path-shaped log value is the matched **route template** (e.g. `/unsubscribe/{token}`), never the raw request path. **Exit check:** the new middleware-level facts in `tests/wa.api.integration/NeutralLogSlotTests.cs` pass (no file name in the business-error line, no unsubscribe token / decoded email in the 500 line or in the request-log properties), `SameTokenTwice_SecondCallStill200_OnlyOneRow` also asserts the no-op line positively, and `node scripts/check-telemetry-pii.mjs` + `selftest` stay PASS with R7 extended.

**D-1 Business error line: log `{Code}` + `{Status}` only, drop `{Message}`.** Simplest provably safe option: an allow-list of "PII-free codes" would still depend on every future throw site's detail text. The correlationId (log context, FR-056-1) links the line to the response, and the Problem+JSON body keeps `business.Message` unchanged (`GlobalErrorMiddleware.cs:32` — the uploader seeing their own file name is fine; TA-4.1.3 shape untouched). Inner exception stays attached to the exception object, not logged here (unchanged).

**D-2 One route-template helper, used by both log sites.** New `src/wa.api/Middleware/LogRoute.cs` (`public static class LogRoute`) — a deep, tiny module that owns "what path-shaped value may be logged":
- `Of(HttpContext)` → `(context.GetEndpoint() as RouteEndpoint)?.RoutePattern.RawText ?? Unmatched`, with `public const string Unmatched = "(unmatched)"`. Route templates are compile-time constants in `Program.cs` → never PII. Unmatched requests (scanner noise, 404) lose their path in logs — acceptable: TA-9.4 forbids raw PII and arbitrary paths can carry anything.
- `RequestLogProperties(HttpContext, string requestPath, double elapsedMs, int statusCode)` → the four `LogEventProperty` values Serilog's default template expects (`RequestMethod`, `RequestPath` = `Of(context)`, `StatusCode`, `Elapsed`), ignoring the raw `requestPath` argument. Wired in `Program.cs:171` via `options.GetMessageTemplateProperties = LogRoute.RequestLogProperties`. Keeping the property name `RequestPath` and the default template means existing queries/dashboards keep working; only the value is scrubbed. Least-invasive: no new middleware, no new package (Serilog.AspNetCore 10.0.0 already referenced, `src/wa.api/wa.api.csproj:10`).
- Endpoint availability: `Program.cs` never calls `UseRouting` explicitly, so WebApplication inserts routing at the pipeline head — the endpoint is set before CorrelationMiddleware/GlobalErrorMiddleware/Serilog run, and both log sites read it after `_next` returns/throws.
- Placement: `wa.api.Middleware` (same namespace as GlobalErrorMiddleware/ProblemWriter); ASP.NET + Serilog types stay in the API layer (onion rule, TA-0.2 #7).

**D-3 Tests at middleware level (no containers).** Getting a real 500 on a token-bearing path at integration level would need a fault injected into `UnsubscribeService` (sealed, DB-bound) — not worth it. The brief allows a DefaultHttpContext test: construct `GlobalErrorMiddleware` directly with a capturing `ILogger<GlobalErrorMiddleware>`, a throwing `RequestDelegate`, and `context.SetEndpoint(new RouteEndpoint(…, RoutePatternFactory.Parse("/unsubscribe/{token}"), 0, null, null))`. `ProblemWriter.WriteAsync` needs no setup (`CorrelationContext.CorrelationId` falls back to a fresh id, `src/wa.domain/Correlation/CorrelationContext.cs:12`). Use a `MemoryStream` response body to also pin that the body still carries the business detail (D-1: body untouched).

**D-4 Extend guard R7 (`scripts/check-telemetry-pii.mjs`).** Add a member-access check on the stripped logger arguments: `/\.\s*(?:Path|PathBase|QueryString|Message)\b/` → reason `argument .<Member> member (raw request path / exception message — log LogRoute.Of(..) / a code instead)`. Tree check (multiline grep over `src/**/*.cs`): the only hits today are `GlobalErrorMiddleware.cs:33` and `:38`, both removed by this task → scan stays clean. `{BlobPath}`/`blob.BlobPath` do not match (`\.BlobPath` ≠ `\.Path\b`). Not adding `path`/`message` to LOG_PII_WORDS (would flag `{BlobPath}`/`{TempPath}`). Selftest: seeded S23/S24, clean C13/C14.

## 4. Open Questions / Risks

- **Serilog wiring is verified by compile + review, not by a captured Serilog event.** The request logger writes through the host-configured Serilog pipeline (`Program.cs:28`), which a test cannot tap without a custom sink + reconfiguration; the delegate itself is unit-tested (step 4, fact 4). Acceptable residual.
- **Unmatched routes log `(unmatched)`** — loses the raw path of 404 probes in logs. Intentional under TA-9.4 (arbitrary paths can carry anything); App Insights request telemetry/Front Door logs remain the place for raw paths if ever needed (out of scope).
- **R7 member check is a text scan** — a raw path laundered into a local (`var p = ctx.Request.Path; _logger.LogX("{P}", p)`) escapes it, same documented limitation as T-012-06.
- No DECISION needed: TA-9.4/9.6 already forbid raw emails/file names in logs; no new package, env var, schema or limit change.
