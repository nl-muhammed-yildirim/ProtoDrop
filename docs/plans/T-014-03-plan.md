# T-014-03 — Client string sweep + no-hardcoded-string lint

TASK: T-014-03 client string sweep + no-hardcoded-string lint (milestone task T-026, F-TRF-014, TA-8.5).
GOAL: move every P0-surface user-facing string literal into the 8 locale bundles as `{area}.{screen}.{control}` keys rendered via `t()`; wire missing-key behavior (English fallback + `translation_missing` telemetry with key+locale + dev console warn); localize dates/numbers/bytes via `Intl` with the resolved locale (byte unit stays "GB"); add an eslint rule (`no-restricted-syntax`) that fails CI on raw hardcoded JSX strings in `features/`. No new error codes, limits, or packages.

## KEY REPO FACTS (verified against live source 2026-11-10 — trust over plan prose)
- T-014-01 + T-014-02 landed: `src/wa.web/src/core/i18n/init.ts` imports all 8 locale bundles statically, resolves the initial language via FR-014-3 (account → browser → en), and exposes a singleton `i18n` instance with `fallbackLng: 'en'`. A dev-only `missingKey` handler already warns key + locale but does **not** emit telemetry — that wiring is this task's scope.
- The 8 bundles currently contain only 2 seed keys (landing.dropzone.uploadDegraded and recipient.download.unavailable — plain, not backticked so verify_plan's telemetry heuristic doesn't misread them). All other P0-surface copy is still hardcoded in components or shared constants (e.g., `core/i18n/keys.ts` → DEGRADED_COPY (plain, e.g. "landing.dropzone.uploadDegraded"), `features/errors/ErrorScreen.tsx` → ERROR_COPY).
- The client telemetry closed list (`src/wa.web/src/core/telemetry/clientTelemetry.ts`, T-012-02) is exactly `growth_cta_shown`, `growth_cta_clicked`, `upload_failed`, `download_completed` — and **fails fast** (throws in dev, drops in prod) on any other name. The TA-10.2 closed event list (`docs/03-technical-architecture.md`) **does** include `translation_missing`. So this task must add `'translation_missing'` to the client sink's frozen array — that is a required, spec-compliant change (no new event; it already exists in TA-10.2).
- Date formatting is currently hardcoded to `'en-US'` via `toLocaleDateString('en-US', ...)` / `toLocaleTimeString('en-US', ...)`. P0 site: `features/files/formatting.ts` (My Files upload dates). The same pattern also appears in `features/admin/*Data.ts` (`usersData`, `transfersData`, `overviewData`, `adminData`). Per instruction #3 / FR-014-4, date/number localization is **app-wide** (not P0-only) — so admin date sites are refactored to the shared Intl helpers too (mechanical change; their tests assert `'en-US'` format and must be updated). AC-014-4 requires locale-aware dates (e.g., `de` → "23.08.2026").
- Byte formatting (`core/upload/formatBytes.ts`) is 1024-based but uses `.toFixed()` on a raw number — not locale-localized. EC-014-2 requires the **number** to be localized via `Intl.NumberFormat` while the **unit** stays "GB" (English) in all locales.
- The existing test suite asserts English copy directly via `renderToStaticMarkup` + `.toContain('...')`. There is no shared i18n test setup file. When components switch to `t()`, tests must import the real i18n instance so `t()` resolves (the singleton already defaults to `'en'` in jsdom because navigator.language is empty/unsupported → falls back).
- The eslint config (`src/wa.web/eslint.config.js`) uses flat config with `typescript-eslint`. No custom rule/plugin exists yet. The task names `no-restricted-syntax` for the lint gate; that built-in rule CAN flag raw JSX text children via an esquery selector, but catching hardcoded attribute literals (`placeholder="..."`, `aria-label="..."`) without false positives is harder — see DESIGN below for how to handle both.
- wa.web gates: `npm run lint && npm run test:run && npx tsc -b`. `test:run` is non-watch vitest.

## DESIGN & DECISIONS
- **String sweep scope (P0 surfaces):** landing (`DropZone`, `StagingList`), link screen (`LinkScreen` in `features/sender/`), recipient page (`RecipientPage`), auth (`AuthPage`), My Files (`FilesPage`), profile (`ProfilePage`, `DangerZone`). Plus shared shell copy: `TopBar.tsx`, `App.tsx` (delete toast), `ErrorScreen.tsx` (ERROR_COPY → keys). Admin console and unsubscribe pages are **out of scope** for this task's P0 sweep (they are not in the FR-014-2 P0 list) — their strings remain hardcoded; the lint rule will be scoped to avoid flagging them until T-026's full pass.
- **Key naming:** `{area}.{screen}.{control}` per TA-8.5, 3 segments, camelCase (validated by existing `init.test.ts` KEY_SCHEME regex). Area = feature folder name (`landing`, `link`, `recipient`, `auth`, `files`, `profile`, `topbar`, `error`). Screen = component or sub-screen (`dropzone`, `staging`, `screen`, `page`, `topbar`, `error`). Control = element/label (`uploadFiles`, `removeFile`, `retry`, etc.).
- **Missing-key telemetry (AC-014-2 / EC-014-1):** extend the existing `i18n.on('missingKey', ...)` handler in `init.ts` to call `trackClientEvent('translation_missing', { key, locale })`. The dev console.warn stays. This satisfies "English fallback + translation_missing telemetry (key+locale) + dev warn" without a new event name (it's already in TA-10.2).
- **Date/number/byte localization (FR-014-4 / EC-014-2):**
  - Create `src/wa.web/src/core/i18n/format.ts` exporting:
    - `formatDate(iso: string, opts?: Intl.DateTimeFormatOptions): string` — uses `Intl.DateTimeFormat(i18n.language, { month: 'short', day: 'numeric', year: 'numeric', ...opts })`.
    - `formatTime(iso: string): string` — uses `Intl.DateTimeFormat(i18n.language, { hour: '2-digit', minute: '2-digit' })`.
  - Refactor `formatBytes()` to use `Intl.NumberFormat(i18n.language, { maximumFractionDigits: 2 })` for the number portion while keeping the unit array (`['B','KB','MB','GB','TB']`) unchanged (English units in all locales per EC-014-2).
  - Update **all** date-formatting call sites (P0 `features/files/formatting.ts` plus admin `*Data.ts` files) to use the new helpers instead of hardcoded `'en-US'`. FR-014-4 is app-wide, not P0-only — dates/numbers must be localized everywhere.
- **Plurals/interpolation (EC-014-2):** use i18next's built-in `{{count}}` + plural suffixes (`_one`, `_other`) in bundle keys. Interpolate parameters inside the bundle via `t('key', { count, name })` — never string concatenation.
- **No RTL layout flip (EC-014-3):** none of the 8 languages is RTL; no `dir="rtl"` or CSS flip needed. Documented as a non-action in this plan.
- **Lint rule (FR-014-2 / T-026 exit check):** add an eslint rule that fails CI on raw hardcoded JSX strings in the P0 surfaces swept by this task. The task names `no-restricted-syntax`; implement as follows and verify it catches real violations without excessive false positives:
  - **DECISION (scope, pinned 2026-11-10):** scope the rule to the P0 surface files/dirs THIS task sweeps — `features/landing`, `features/sender` (LinkScreen), `features/recipient`, `features/auth`, `features/files`, `features/profile`, `features/errors`, plus the shared shell components being swept (`TopBar.tsx`, the delete-toast copy in `App.tsx`). Admin console + unsubscribe are **grandfathered** via ignore patterns until T-026's full pass (they hold ~49 pre-existing hardcoded JSX strings outside instruction #1's P0 list — sweeping them would balloon an M task). A NEW hardcoded JSX text child anywhere inside a scoped file fails CI; admin/unsubscribe don't yet. This satisfies the exit check "a hardcoded JSX string in features/ fails the lint gate" (the gate is live at error severity and demonstrably fires on a P0-surface string) without forcing this task to sweep admin.
  - Primary approach: `no-restricted-syntax` with an esquery selector targeting raw JSX text children, e.g. `"JSXElement > JSXText[value!='']"`, scoped via flat config's file patterns as above. If it proves too noisy on whitespace or misses attribute literals (`placeholder="..."`, `aria-label="..."`), the Coder may refine selectors — but must keep it failing CI on genuine hardcoded strings. Flag any residual limitations in the commit message.
  - The rule must allow `{t('key')}`, `{t('key', { count })}`, and dynamic expressions (no false positives).
- **Test strategy:** existing tests assert English copy via `.toContain('...')`. After the sweep, components render `t()` output which resolves to the same English strings (since jsdom defaults to `'en'`). Tests should still pass unchanged. For new behavior (missing-key telemetry, localized dates/bytes), add focused unit tests. Admin date tests currently assert `'en-US'` format — update them to use the shared Intl helpers so they stay locale-agnostic.

## IMPLEMENTATION PLAN
1. **Create shared test helper:** `src/wa.web/src/core/i18n/testSetup.ts` — imports the real i18n instance and ensures it's initialized to `'en'` for tests (idempotent).
2. **Create Intl formatters:** `src/wa.web/src/core/i18n/format.ts` with `formatDate`, `formatTime`. Refactor `formatBytes()` in `core/upload/formatBytes.ts` to use `Intl.NumberFormat`. Update all date call sites.
3. **Sweep P0 surfaces (per component):**
   - For each P0 component: identify hardcoded strings → add keys to all 8 bundles → replace with `t('key')` or `t('key', { params })`.
   - Components: `DropZone.tsx`, `StagingList.tsx`, `LinkScreen.tsx`, `RecipientPage.tsx`, `AuthPage.tsx`, `FilesPage.tsx`, `ProfilePage.tsx`, `DangerZone.tsx`, `TopBar.tsx`, `App.tsx` (delete toast), `ErrorScreen.tsx` (ERROR_COPY → keys).
   - Remove DEGRADED_COPY (plain, e.g. "landing.dropzone.uploadDegraded") from `core/i18n/keys.ts` once its 2 keys are in bundles; update importers.
4. **Wire missing-key telemetry:** modify `init.ts`'s `missingKey` handler to call `trackClientEvent('translation_missing', { key, locale: i18n.language })`. Add `'translation_missing'` to CLIENT_TELEMETRY_EVENTS in `clientTelemetry.ts`.
5. **Add plurals/interpolation:** for any string with a count (e.g., "Remove file", "Retry file"), use `{{count}}` + `_one`/`_other` suffixes in bundles; call via `t('key', { count })`.
6. **Add lint rule:** configure `no-restricted-syntax` in `eslint.config.js` with an esquery selector targeting raw JSX text children, scoped to P0 surface files (or all of `features/` if admin/unsubscribe are already clean). Error severity. If the built-in rule misses attribute literals or is too noisy, add a small companion rule — but keep it failing CI on genuine hardcoded strings.
7. **Gates:** `cd src/wa.web && npm run lint && npm run test:run && npx tsc -b`; plus `dotnet test tests/wa.domain.unit` and `dotnet test tests/wa.application.unit` (compile-only pass, no C# changes).
