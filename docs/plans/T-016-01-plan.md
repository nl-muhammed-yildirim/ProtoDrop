# T-016-01 — useAriaLive helper + hidden live-region containers in core/ui

TASK: T-016-01 useAriaLive helper + hidden live-region containers in core/ui (F-TRF-016, milestone task T-027 part 1).
GOAL: add a useAriaLive helper to wa.web src/core/ui that owns one hidden live-region element mounted with its screen (existing before any update), single-sources the polite → role=status / aria-live=polite and assertive → role=alert mapping, throttles progress announcements to exactly 0/25/50/75/100 percent (endpoints inclusive — a 99→100 jump is always announced), and collapses bulk updates into one summary announcement; unit tests prove the throttle and on-mount container behavior.

## DESIGN & DECISIONS
- **D-1 File layout (core/ui):** three files, all new: useAriaLive.ts (React hook), ariaLiveThrottle.ts (pure, framework-free throttle + bulk-collapse logic — unit-testable without React), useAriaLive.test.tsx (colocated tests). Keeping the throttle pure mirrors the repo convention of testable core modules (resolveTheme.ts / UploadEngine.ts pattern).
- **D-2 Single-sourced mapping:** the hook's render output is the ONLY place where priority → ARIA attributes happens: polite renders a div with role=status and aria-live=polite; assertive renders a div with role=alert. No other file in this task writes those attributes. The element is hidden via an inline style (visually-hidden pattern: absolute, 1px clip) — pure CSS/inline state, no third-party kit (TA-8.2), and it is rendered unconditionally on the first render so it exists before any update (US-016-02 Edge cases).
- **D-3 Container ownership:** the hook returns a JSX element (the hidden container) plus an announce(message: string) callback. Screens render the returned element inline in their tree (mounted with the screen); announcements write textContent via the ref directly — no React state, so announcing never re-renders the screen and the region is never created on first use.
- **D-4 Throttle algorithm:** a ProgressThrottle class holds lastAnnounced: number | null. onProgress(percent): number | null returns the percent to announce or null. Rule: announce if (a) percent >= 100, or (b) lastAnnounced is null and percent === 0, or (c) there exists a point p in {25, 50, 75} with lastAnnounced < p <= percent. A 99→100 jump hits rule (a) → always announced; repeated ticks at the same point never re-announce; announcing at 100 resets lastAnnounced to null so a subsequent upload run re-announces from 0.
- **D-5 Bulk collapse:** a pure summarizeFailures(messages: string[]): string | null returns null for an empty array and one summary line (e.g. "3 files failed" — count + i18n key, not per-message text) for any non-empty batch. The hook's announce() is the single write path, so N failures routed through it in one tick produce exactly one summary announcement (US-016-02 Alternative flows).
- **D-6 No network on announce:** announce only mutates the hidden region's textContent — no fetch, no telemetry (US-016-02 Technical notes: live regions are pure UI state).

## CONSTRAINTS
- wa.web only — no .NET diff; dotnet gates compile-only.
- No third-party a11y kit (TA-8.2): live regions are pure UI state — no network calls on announce.
- The priority → ARIA attribute mapping lives in exactly one place (the hook's render output) so screens cannot drift per screen (US-016-02 Edge cases).
- Throttle: progress announces at 0/25/50/75/100 percent only; endpoints inclusive — a 99→100 jump is always announced.
- Bulk updates (e.g. multiple failed files) collapse into ONE summary announcement ("3 files failed" shape).
- Placement contract (for T-016-02, documented here): one hidden role=status container per stateful screen — upload list (StagingList.tsx section.sl), password card (RecipientPage.tsx form.rp-password-card); toasts follow UI-Reference §4.3 and do NOT use the helper's container.

## ASSUMPTIONS
- DECISION: the throttle points {0, 25, 50, 75, 100} are a client-side UI constant inside ariaLiveThrottle.ts (not in the Limits Registry / Open-Decisions Part 2) — they are an accessibility pacing choice from EC-016-1, not a transfer limit; no escalation needed.
- DECISION: announce writes textContent via ref instead of React state to guarantee the region is never recreated on first use and announcing does not re-render the screen (US-016-02 Edge cases); this matches the "container mounted with its screen" contract.
- ASSUMPTION: the summary announcement wording ("N files failed") uses an i18n key added by T-016-02 when it wires screens; this task's summarizeFailures returns a count-bearing line whose exact copy is left to that wiring (US-016-02 Alternative flows only fixes the shape).
