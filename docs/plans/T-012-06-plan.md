# T-012-06 Plan — No raw email in plain ILogger lines

**Task row:** `docs/features/Phase 0-MVP/F-TRF-012/F-TRF-012-telemetry.md:87` (US-012-01, gap task 2026-11-17, user decision; no story task file).
**Spec:** TA-9.4 (`docs/03-technical-architecture.md:783` — PII = email addresses, sender names, file names, IPs; raw PII only in `DownloadEvent` / `AppUser` / `EmailRecipient` rows), EC-012-3 / AC-012-3 (`docs/02-feature-plan.md`), follow-on to T-012-05 (`docs/plans/T-012-05-plan.md`, `scripts/check-telemetry-pii.mjs`).

## 1. Goal

No `ILogger` line in `src/` carries a raw email address / sender name / file name / IP, and `scripts/check-telemetry-pii.mjs` gains a rule R7 that fails the build if one reappears. **Exit check:** the three call sites log only non-PII correlators (proved by unit facts that capture logger output), `node scripts/check-telemetry-pii.mjs` = PASS with R7 0 over a non-zero logger-call count, `selftest` catches every new seeded case.

**D-1 Drop the address, log a non-PII correlator — no new transform.** TA-9.4 sanctions exactly two transforms: file name → SHA-256 and IP → HMAC(`Wa:Jwt:Secret`) (`src/wa.domain/Telemetry/PiiTransforms.cs:13,17`). Neither is defined for emails, and an *unkeyed* SHA-256 / short prefix of an email is dictionary-reversible (emails are low-entropy), while a domain-only mask still leaks. Inventing an email transform would be a new PII/security-shaped choice (AGENT.md §7) — avoided entirely: every site already has a stable non-PII id or needs none. The request correlationId (T-056-01 log-context enrichment) links the line to the rest of the trace.
- Signup → `"User created {UserId}", userId` (the `userId` local at `Signup.cs:73`).
- SendNotificationEmails → `"f-email: failed to send email to recipient {RecipientId} attempt {Attempt}", recipient.Id, attempt` (`EmailRecipient.Id`, `src/wa.domain/EmailRecipient.cs:6`; same id already lands in `notifiedIds`).
- UnsubscribeService → `"Unsubscribe idempotent no-op — suppression row already exists (UQ_ES)"`, no properties (there is no row id on the duplicate path, and none is needed — the 404/200 outcome + correlationId suffice).

**D-2 Guard rule R7 (`check-telemetry-pii.mjs`) — logger calls, any receiver.** Mirrors the T-012-05 choice (match by method name, not receiver name, so renaming the field cannot dodge it). Pattern LOG_CALL_RE = /\.\s*Log(?:Trace|Debug|Information|Warning|Error|Critical)?\s*\(/g over masked code; does **not** match `LogEvent(` (reporter) because the level group is followed by `\s*\(`. Runs on **every** `.cs` file (reporter file included — its templates pass). One R7 finding per call, listing all reasons:
1. EMAIL_RE on the argument text (literal / template) → raw email literal.
2. Every `{placeholder}` in the argument text (`/\{(\w+)(?::[^}]*)?\}/g` over `nc`) whose identifier is PII-named (rule below).
3. Every identifier in the argument **code** after `stripSanctioned` (removes `TelemetryEvents.X`, `PiiTransforms.FileName/IpAddress(..)`, `FileNameSlot/IpSlot(..)`) that is PII-named, plus any `.Name` member access (e.g. `file.Name`). C# interpolation holes stay visible in `code` (`mask`, line 171), so `$"..{user.Email}"` is caught here.

PII-named identifier (new `isLogPiiIdentifier(id)`): split into words with the existing camel/snake splitter; PII if any word ∈ LOG_PII_WORDS = {email, mail, address, ip, password, passwd, secret, sas, sig, signature}, **or** the words contain `name` together with a qualifier ∈ NAME_QUALIFIERS = {file, sender, display, user, recipient, owner}. Bare `name` is *not* PII here (unlike R2's PII_WORDS): `BlobContainerBootstrap.cs:53` logs a container `name`, `AzureBlobStore.cs:30` an `accountName`, the reporter an `eventName` — R2's word set would make R7 noisy on legitimate config names. Tradeoff recorded in the script header Limitation.

**D-3 Counts / vacuity.** `scanTree` counts `logCalls`; `runScan` fails vacuously when it is 0 (same rule as the other surfaces), prints the count and an `R7` row. Header comment: add R7, and replace "T-069 owns … general _logger templates" with "T-069 owns the [Pii] attribute and event-DTO convention tests".

**D-4 Tests capture logger output.** New shared generic test logger `CapturingLogger<T>` in the wa.application.unit test project (records level, `formatter(state, ex)` text, and structured values from the state's `KeyValuePair` list, excluding `{OriginalFormat}`) — the existing recorders (`SignupHandlerTests.TelemetryRecorder`, `CreateDraftHandlerTests.RecordingLogger`) are typed to `ILogger<WaTelemetryReporter>` and are left untouched (no drive-by refactor). The UnsubscribeService duplicate path is unreachable on the InMemory provider (no unique constraints — `UnsubscribeServiceTests.cs:89`), so the unit fact forces it with an EF Core `SaveChangesInterceptor` that throws `DbUpdateException` (EF Core built-in, no package — golden rule 1); the SQL-backed integration fact gets one extra negative assertion.

TA citations: TA-9.4 (policy), TA-10.2/TA-10.5 (closed telemetry, Serilog stack only), TA-0.2 rule 7 (no layer change — edits stay in their own projects).

## 5. Open Questions / Risks

1. **`LogEmailSender` (dev transport) logs `To`/`From`/`ReplyTo` + bodies (sender name, file names) raw** — out of scope here: it is the `Wa:Email:Sender=log` transport, not a diagnostic line, and an E2E fact depends on its output. R7 does not flag it (placeholders `To`/`From` are not PII-named words). Residual risk: if `Wa:Email:Sender=log` were ever set outside Local/CI, real emails would reach App Insights. Suggested follow-up (orchestrator to log, non-blocking): refuse `log` when ASPNETCORE_ENVIRONMENT/Functions environment is Production, or hand it to T-069.
2. R7 is a text scan: a PII value laundered through a neutrally named local (`var x = user.Email; _logger.LogX("{X}", x)`) escapes it, and bare `name` is deliberately not PII. Same limitation class as R2; the three fixed sites are additionally pinned by unit facts.
3. LOG_CALL_RE would also match a non-logger `.Log(` (e.g. `Math.Log(`) — none in `src/` today; if one appears, handle it narrowly in the script.
4. Docs close-out (orchestrator): extend the `docs/AGENT.md` §4 pii-check gate comment to mention ILogger calls (R7); tick the row in `F-TRF-012-telemetry.md:87`.
