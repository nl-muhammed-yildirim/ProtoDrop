# T-015-03 — Full-screen theme parity audit + token-diff CI check

TASK: T-015-03 full-screen theme parity audit + token-diff CI check (milestone task T-027, F-TRF-015).
GOAL: sweep every screen in dark mode and replace hardcoded colors with tokens per UI-Reference §4.5; add a CI script that diffs both [data-theme] token sets and fails on any missing variable per theme (FR-015-2/AC-015-4); add the Playwright check — emulateMedia({ colorScheme: 'dark' }) + data-theme before paint + background assert.

## KEY REPO FACTS (verified against live source 2026-11-13)
- tokens.css (T-015-01): src/wa.web/src/styles/tokens.css defines ALL 14 color tokens in three scopes — :root (light default), html[data-theme='dark'], html[data-theme='light'] — each scope defines the full set (parity holds today; the CI script maintains it).
- index.html pre-paint script always sets data-theme="dark"|"light" before first paint (T-015-01) → Playwright can assert the attribute on first frame.
- **Complete hardcoded-color inventory** (grep of every .css + .tsx): ONLY src/wa.web/src/index.css — 10× color: #FFFFFF (button text), 2× box-shadow: 0 1px 2px rgba(0, 0, 0, .06) (.dz-toast line 132, .tb-dropdown line 666), 1× background: rgba(16, 20, 24, 0.5) (modal scrim). Zero hardcoded colors in TSX inline styles or any other CSS file (errorMap.css / recipient.css are token-only).
- **Button text #FFFFFF is a documented contract** — UI-Reference §4.5 documents primary = accent background + white text, danger = danger background + white text. Both palettes' accent colors (#4185F4 light / #5A9BF7 dark) keep ≥ 4.5:1 with white → these are NOT parity defects; the audit verifies contrast via token values (US-015-02 edge case), not by rewriting them.
- **Elevation rule** (UI-Reference §3 + F-TRF-015 spec line 57): light = border + shadow; dark = a flat 1px ring in the border color, no shadow → the two .dz-toast / .tb-dropdown shadows need a dark-theme override to that flat ring (box-shadow with a 0 0 0 1px spread in the border token from tokens.css — the only border-named color token) — same element set, no layout change.
- Modal scrim rgba(16, 20, 24, 0.5): shared across both themes (darkening overlay reads correctly in either palette) → keep as-is, documented out of scope.
- CI (.github/workflows/ci.yml): jobs lint-web / lint-dotnet / unit / integration / web / docker — no theme job yet; header comment says "adding a job requires updating both files" (AGENT.md §4). Playwright is already a dev-dep (@playwright/test ^1.64.1); e2e specs live in src/wa.web/e2e/ with global-setup (Azurite CORS) — the new spec follows that pattern; e2e runs locally via docker-compose stack, NOT in CI at M0 (no playwright job).
- No C# changes: dotnet gates just compile.

## DESIGN & DECISIONS
- **D-1 Parity sweep**: the audit's real fixes are exactly two — dark-theme elevation override for .dz-toast + .tb-dropdown to a flat ring in the border color token from tokens.css (per UI-Reference §3). Button #FFFFFF text and the modal scrim stay, each with a one-line comment citing the contract. No other hardcoded colors exist in the app (inventory above is exhaustive — verified by grep across all .css/.tsx).
- **D-2 Token-diff CI**: new script at scripts/check-theme-tokens.mjs (repo root, next to verify_plan.py/azurite-cors.js): parse tokens.css, extract custom properties per scope (:root / [data-theme='dark'] / [data-theme='light']), assert each of the 14 token names is present in ALL three scopes and that dark ≠ light for every color (catches copy-paste drift where a "dark" value equals the light one), exit 0/1. Wired into ci.yml as a new theme-check job (checkout + setup-node only — no npm install needed, plain node script) AND listed in AGENT.md §4 gate table per the workflow's own rule.
- **D-3 Playwright**: new spec src/wa.web/e2e/theme-parity.spec.ts with three tests: AC-015-4 (emulateMedia dark → data-theme="dark" on first frame + body background is #0F1115 — the dark palette's page-background token value), AC-015-1 (account theme=dark in session mirror 'protoDrop.session' via addInitScript before navigation → no light flash: data-theme="dark" on first frame), AC-015-3 (system mode + emulateMedia switch light→dark mid-session → data-theme flips to "dark" without reload — exercises the T-015-02 useSystemTheme hook in a real browser).
