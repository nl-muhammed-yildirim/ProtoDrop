# T-013-03 Implementation Plan — Blob-down detection & mapping (upload ladder + SAS mint)

## TASK
T-013-03: Blob-down detection & mapping for the API half of AC-013-2.
Add per-file, block-level blob 503 detection to the upload ladder (client) and to endpoint 7's mint path (server), mapped as **503 + code INTERNAL** — no new closed-list Problem+JSON codes, no global degradation flag, no in-flight interruption handling.

## GOAL
When the Blob account is down:
- Upload half: the existing 5-retry ladder runs on block-level blob failures; after the last retry the row is marked failed with a distinct "storage unavailable" reason so T-013-04 can render FR-013-3's copy (row-local, not the generic 500 screen).
- Download half: endpoint 7's mint path (the only MVP server-side blob call at mint time — `GetDownloadAllUrlQuery` L95 `_blobStore.ExistsAsync(zipPath)`) catches `RequestFailedException`/503 and returns a new enum state mapped to **503 + code INTERNAL**. Endpoint 6 mints are pure HMAC (no network call in MVP) and cannot throw blob 503 — no change needed there.
- Per-file: one file's mint failure does not hide the file list or affect other rows in the same transfer.

### TA-10.2 (telemetry event vocabulary — relevant rows only)

## DECISION LINE (telemetry)
**Option chosen: B — reuse existing event name.**
Rationale: T-013-02's verification script enforces a 1:1 map between TelemetryEvents.cs and TA-10.2 literals; adding `download_mint_failed` would require modifying both the documentation AND the constant file, violating the "no new machine codes or limits" constraint. The existing event set already covers mint-time failures via other events (e.g., zip_failed for endpoint 7's zip path). For T-013-03, we will:
- Add a `reason` property to the existing `upload_failed` emission in UploadEngine.ts L154 to distinguish blob 503 from generic failure.
- NOT add a new telemetry event for mint failures — the 503 rate on endpoint 6/7 is visible in F-TRF-012 dashboards via HTTP status codes, no new metric definitions needed (per task file instruction #3).
