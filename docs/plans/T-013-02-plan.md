## ASSUMPTIONS / DECISIONS
- **DECISION:** use --fs-h1 (28px) for the §4.6 error line because there is no --fs-h2 in :root — it is the closest real token to a sub-display heading size and matches how other page-level headings render; adding a new token would be out of scope for this task.
- **DECISION:** Try again re-issue mechanics — ErrorScreen takes an onAction callback prop (no full reload unless the failing action was a page load). AppErrorBoundary passes window.location.reload() because a client-side render error IS a page-load failure; API-error callers pass their own retry handler (re-fetch / re-issue the failed call).
- **DECISION:** i18n — no i18next package is installed yet (T-026 owns the 8-locale pass), so all error copy lives as translation-key constants in ErrorScreen.tsx with English values verbatim from spec. Keys follow TA-8.5's {area}.{screen} pattern: errors.somethingWrong.title, errors.somethingWrong.tryAgain, errors.notFound.title, errors.notFound.goHome, errors.refLabel (the "Ref:" label — localized; the 8-hex id is never a key).
- **Assumption:** the code → screen/state map lives in src/wa.web/src/core/api/errorMap.ts per TA-8.2's core/api placement ("fetch wrapper: Problem+json → typed errors"); features import from it (core/ is import-only — no feature-to-feature imports).
- **Assumption:** the 404 screen has NO Ref line because no API request happened for an unknown SPA route (per task file instruction #1); only the 500 screen shows Ref.
- **Assumption:** the 60 s hint is part of the RATE_LIMITED copy per spec ("A moment of calm, then try again." with the 60 s hint) — rendered as one line in the same §4.6 layout shape; no separate countdown timer or new constant.
