## ASSUMPTIONS / DECISIONS
- DECISION (shared data module): one adminData.ts holds all three wire types + formatCreatedAt — the Flags screen needs flag + audit-recent types, Suppressions needs suppression type, and formatCreatedAt is shared by both; a single module avoids duplicating the date helper across two files.
- DECISION (no client-side JSON validation): the textarea value is PUT as the raw body string verbatim; the server validates before commit (T-011-08), so on 400 VALIDATION the old value stays live in the field — no optimistic update, no local parse.
- DECISION (audit panel placement): the Recent actions panel renders ONLY on the Flags screen (per spec: "ON THE FLAGS SCREEN"), not on Suppressions.
- DECISION (no new endpoints / hints verbatim): only 23 GET/PUT, 24 GET/DELETE, 25 are used; both hint strings appear exactly as pinned in the task.
- ASSUMPTION: senderEmail null renders as '—' in the Suppressions table (the wire allows null); no dedicated "no sender" UI beyond that.
