# T-006-07 Plan — workers settings via IConfiguration

**Feature:** F-TRF-006 (Email) · **Story:** US-006-01 · **Size:** S
**Architecture:** TA-0.2 rule 7 (adapter picked by config), TA-6.2 (function inventory, Flex Consumption), TA-9.3 (Key Vault secrets: `Wa:Jwt:Secret`, blob key), TA-9.4 (no secrets in logs/messages), TA-13.1 (wa-workers env vars).
**Task file:** none — gap task approved 2026-11-17 (`docs/Open-Decisions-and-Constants.md` Part 3, row "wa.workers colon-named env reads", Option A). This plan is the contract.

## 1. Goal

Every setting the workers host reads at composition goes through IConfiguration (so the Linux `Wa__X` app-setting form works), with the same key names and no new env vars. **Exit check:** the new `tests/wa.workers.unit/WorkerServicesTests.cs` facts are green — Service Bus key present → SbEventPublisher, absent → InMemoryEventPublisher, `Wa__…` environment variables are picked up (blob URL, JWT secret, SB), missing blob URL fails with the key name — and `dotnet build src/wa.slnx` is clean.

## 2. Design & Decisions

### Grounding facts (verified)
- `src/wa.workers/Program.cs:20` adds env vars to IConfiguration; the env provider maps `Wa__Blob__AccountUrl` to key `Wa:Blob:AccountUrl`. But composition never reads IConfiguration for these keys:
  - `Program.cs:29-30` `Environment.GetEnvironmentVariable("Wa:Blob:AccountUrl" / "Wa:Blob:AccountKey")`
  - `Program.cs:49` `"Wa:Jwt:Secret"` (HMAC key for the IP slot, TA-9.4)
  - `Program.cs:59` `"Wa:ServiceBus:ConnectionString"` — chooses SbEventPublisher vs InMemoryEventPublisher.
  - `Program.cs:25,56` `"WaDb"` (no colon; works on Linux, but still a raw env read).
- Confirmed bug: SbEventPublisher already reads `configuration["Wa:ServiceBus:ConnectionString"]` (`src/wa.infrastructure/Events/SbEventPublisher.cs:31`), but the selection at `Program.cs:59` uses the raw colon name. On a Linux Flex host (`docs/04-production-plan.md:72`) the value lives under `Wa__ServiceBus__ConnectionString`, so the check is always empty → InMemoryEventPublisher → every worker-published event (transfer.expired, email.sent, …) is lost silently. Blob reads would be null → the eager `new DraftBlobSasMinter(new Uri(null!) …)` at `Program.cs:35` crashes the host at startup. The JWT secret falls back to `""` → IP HMAC with an empty key.
- Other `Environment.GetEnvironmentVariable(` calls: grep over `src/` finds only these six (all in `src/wa.workers/Program.cs`). Functions already use IConfiguration: `JobAuth.cs:13` (`Wa:Jobs:SignKey`), `ZipFunction.cs:63` (`Wa:Zip:SignKey`), `EmailSenderSelector` (T-006-06). No `local.settings.json` exists; `host.json` has no settings keys.
- `EmailFunction.cs:45` `[ServiceBusTrigger("core", "email", Connection = "Wa:ServiceBus:ConnectionString")]` — the Functions host resolves trigger connection names through its own configuration, which maps `__` to `:`. Fine as-is; out of scope.
- `WaDb` key: the API reads `GetConnectionString("WaDb")` (= `ConnectionStrings:WaDb`, `src/wa.api/Program.cs:38`) and TA-13.1 lists `ConnectionStrings__WaDb` for "wa-api / wa-workers", but the workers read key `WaDb` and `docker-compose.local.yml:76` sets `WaDb`. The task forbids key renames, so the workers keep key `WaDb` (now through IConfiguration). The TA-13.1 drift goes to Open Questions.
- `EmailLogSenderE2ETests` composes its own worker side (`tests/wa.api.integration/Events/EmailLogSenderE2ETests.cs:243`) and does not call Program.cs — not affected. No test references Program.cs composition today.

### D-1: Extract composition into `WorkerServices.AddWorkerServices(IServiceCollection, IConfiguration)`
New `src/wa.workers/WorkerServices.cs` (namespace `wa.workers`, public static class) holds the whole `ConfigureServices` body, moved as-is except for the config reads. Program.cs becomes `.ConfigureServices((context, services) => services.AddWorkerServices(context.Configuration))`.
- Why registration-time `context.Configuration` instead of lazy `sp.GetRequiredService<IConfiguration>()` in factories: the SB choice is a registration decision (one of two descriptors), and the eager DraftBlobSasMinter/AppDbContextFactory registrations already read at composition. One consistent read point beats a mix. HostBuilderContext.Configuration is fully built (incl. the env-var provider from `Program.cs:20`) before ConfigureServices callbacks run.
- Why extract: top-level statements are untestable; the extension is the seam the unit test drives with an in-memory or env-var IConfiguration. It is the deeper module — Program.cs knows no key names.
- No separate `WorkerSettings` record: the keys are used only here; five `public const string` key names on the class are enough (tests pin them).

### D-2: Key reads and failure behavior (no semantic change except clearer errors)
| Key | Read | When missing |
|---|---|---|
| `WaDb` | `configuration["WaDb"] ?? ""` | unchanged (`""`, fails at first DB use) |
| `Wa:Blob:AccountUrl`, `Wa:Blob:AccountKey` | `Require(configuration, key)` | throws `InvalidOperationException("<key> is required.")` at composition — today it already throws (ArgumentNullException from `new Uri(null!)` / BlobSasMinter ThrowIfNull); the message now names the key only (TA-9.4, same style as `EmailSenderSelector.cs:26-28`) |
| `Wa:Jwt:Secret` | `configuration["Wa:Jwt:Secret"] ?? ""` | unchanged fallback (see Open Questions) |
| `Wa:ServiceBus:ConnectionString` | `configuration[key]`, `string.IsNullOrEmpty` check | InMemoryEventPublisher (unchanged local-dev fallback, TA-0.2 rule 7) |

### D-3: T-006-06 reviewer follow-up — not in scope
The missing-CH-connection throw happens when DI builds the email sender, so TA-6.7 step 5's last-attempt email.failed never fires. Fixing it changes the email failure path, not config reads → Open Questions.

## 3. Implementation Plan

1. **Create `src/wa.workers/WorkerServices.cs`.** Move `Program.cs:23-130` (the body of the ConfigureServices lambda) into `AddWorkerServices`, returning `services`. Replace the six env reads per D-2. Move the `using` directives the body needs (all of `Program.cs:3-16` except Functions/Hosting ones if unused). Keep every comment and registration order. Shape:
   ```csharp
   namespace wa.workers;

   /// <summary>T-006-07: wa.workers DI composition; every setting read through IConfiguration so Linux "Wa__X" app settings work (TA-13.1).</summary>
   public static class WorkerServices
   {
       public const string DbKey = "WaDb";
       public const string BlobAccountUrlKey = "Wa:Blob:AccountUrl";
       public const string BlobAccountKeyKey = "Wa:Blob:AccountKey";
       public const string JwtSecretKey = "Wa:Jwt:Secret";
       public const string ServiceBusKey = "Wa:ServiceBus:ConnectionString";

       public static IServiceCollection AddWorkerServices(this IServiceCollection services, IConfiguration configuration)
       {
           var dbConnection = configuration[DbKey] ?? "";
           var blobAccountUrl = Require(configuration, BlobAccountUrlKey);
           var blobAccountKey = Require(configuration, BlobAccountKeyKey);
           // ... moved registrations, using the locals above (drop the `!` suppressions) ...
           var hmacKey = System.Text.Encoding.UTF8.GetBytes(configuration[JwtSecretKey] ?? "");
           var sbConnString = configuration[ServiceBusKey];
           // if (!string.IsNullOrEmpty(sbConnString)) SbEventPublisher else InMemoryEventPublisher — unchanged
           return services;
       }

       private static string Require(IConfiguration configuration, string key)
       {
           var value = configuration[key];
           return string.IsNullOrWhiteSpace(value) ? throw new InvalidOperationException($"{key} is required.") : value;
       }
   }
   ```
   Verify: `dotnet build src/wa.slnx`.

## 4. Open Questions / Risks

- **TA-13.1 drift on `WaDb`:** TA-13.1 lists `ConnectionStrings__WaDb` for wa-workers, code and compose use `WaDb`. Renaming was forbidden for this task; the orchestrator should either fix the TA-13.1 row (workers: `WaDb`) or open a follow-up to read `GetConnectionString("WaDb")` with `WaDb` fallback. No infra-as-code exists in the repo yet, so nothing deployed depends on either today.
- **Empty JWT secret fallback** (`?? ""`) kept to avoid a behavior change; an empty HMAC key weakens the TA-9.4 IP hash. Making it required is security-shaped (AGENT.md §7) — propose as a follow-up, not decided here.
- **T-006-06 follow-up:** a missing `Wa:CommunicationHub:Connection` throws while DI builds the email sender, so TA-6.7 step 5 email.failed never fires for that case. Out of scope (email failure path).
- **Env-var test** mutates process environment; it restores in `finally`, and no other test in the wa.workers.unit project reads these keys from the environment. If flakiness appears, put the class in its own xunit collection with parallelization disabled.
- `Dockerfile` CMD workaround re-exporting colon-named vars (`src/wa.workers/Dockerfile`) stays; it becomes unnecessary once compose switches to `Wa__` names (optional later cleanup).
