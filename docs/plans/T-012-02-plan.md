TASK: T-012-02 Browser telemetry sink

GOAL: Formalize the M0 growth-CTA console.debug sink into a single test-overridable client telemetry sink in src/wa.web/src/core/telemetry/ that (1) routes the two growth CTA events through a client-side closed event list mirroring the server's, (2) emits upload_failed and download_completed from the existing upload/download pages, and (3) POSTs every event to dev App Insights carrying the action's T-012-01 traceparent — so AC-012-1 block 2 holds (all four events appear in dev AI within ~30 s with the right correlationId) and ad-hoc event names fail fast instead of being silently logged.

### ASSUMPTIONS

- **PII slot semantics:** reuse the server's PiiTransforms semantics where the client carries a file name — SHA-256 of the raw name (mirrors WaTelemetryReporter's FileNameSlot). At M0 the client events carry fileId (a Crockford base32 link/file id, not a raw file name) so no hashing is strictly required; if a future event carries a raw file name, apply SHA-256 before emission. No IP in any client event at M0 (TA-9.4/TA-9.6: IP → HMAC-SHA256 keyed by the server secret — but the client does not carry an IP, so no slot needed).
- **download_completed bytes/durationMs are custom properties:** TA-10.2 line 816 shows download_completed has NO contract-named properties (only upload_completed names bytes/durationMs/retries). At M0 with no in-page stream leg, these fields are client-measured custom properties — accepted per the T-003-06 ADR gap ("download_completed lands with the client telemetry pipeline (F-TRF-012)").
- **upload_failed is property-free in the server set:** only upload_completed carries contract-named properties. The client's upload_failed emission carries fileId + retry count as custom properties, not contract fields.
- **growth CTA events are NOT in the server closed set:** the client gets its own closed list (clientTelemetry.ts) mirroring TelemetryEvents.cs for the four client-emitted names. TA-10.2's event list gains both growth names (the contract change). The server set is unchanged — no .cs edits.
- **fetch POST transport:** chosen over the JS SDK on "fewer runtime deps wins" (package.json has 4 runtime deps, none of them an AI SDK; fetch is a browser builtin = 0 new packages). ADR row records this.
