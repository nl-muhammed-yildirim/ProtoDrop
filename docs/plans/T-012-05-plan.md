# T-012-05 Plan — CI PII guard for telemetry

**Task:** T-012-05 (F-TRF-012, US-012-01; gap task 2026-11-17, no story task file — this plan is the contract)
**Spec:** EC-012-3 (PII properties marked / CI grep for raw emails in event helper calls), AC-012-3 (file name SHA-256 hashed, no raw name or secret in any property)
**TA:** TA-9.4 (PII policy + slots), TA-10.2 (names are code; the reporter is the single exit), TA-10.5 (logging rule), TA-17 (no new packages)
**Size:** S–M

## 1. Goal

Add a repo-root, Node-built-ins-only gate `scripts/check-telemetry-pii.mjs` (plus a C# reflection pin on the reporter's string-typed slots) that fails CI when a raw email literal, a PII-named identifier, an unknown property name, or an un-hashed value reaches a server (WaTelemetryReporter) or client (trackClientEvent) telemetry call. **Exit check:** `node scripts/check-telemetry-pii.mjs` PASS on today's tree, `node scripts/check-telemetry-pii.mjs selftest` PASS (every seeded violation flagged, every clean shape passes), new CI job `pii-check` runs both, and `dotnet test tests/wa.application.unit` is green with the two new AC-012-3 facts.

### Decisions

- **D-1 Two tools, split by what each can see precisely.** Method *signatures* are visible to reflection → a C# unit test in `wa.application.unit` pins the closed set of string parameters on `WaTelemetryReporter` (precise, no regex). Call-site *expressions* and Serilog *template text* are not visible to reflection → the Node script scans them. TS has no reflection at all → the script covers the client too. Both run in CI (unit job already exists; script gets a new job). TA-17: zero packages — script uses node:fs / node:path / node:process / node:url only, like `scripts/check-theme-tokens.mjs`.
- **D-2 Closed allowlists, not just a deny-regex.** A deny regex alone misses a new `{userRef}` that happens to carry an address. So each property-name surface is a closed set inside the script, and the PII-word check only sharpens the error message:
  - SERVER_PROPS = bytes, durationMs, retries, sizeBytes, seconds, count, linkId (the placeholders above, exactly).
  - CLIENT_PROPS = fileId, retries, reason, bytes, durationMs, key, locale, source (the keys above, exactly).
  - STRING_SLOT_METHODS = TransferPageViewed (its argument must be slot-wrapped, see R4).
  Adding a property means editing one list in one file — that edit is the PR-visible review point EC-012-3 asks for ("lint/review rule").
- **D-3 Rules (all GATE tier, exit 1; precise definitions the Coder implements):**
  - **R1 email literal** — any string literal inside a helper call's argument text, or inside a reporter template, matching `[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}` fails.
  - **R2 PII identifier in a server argument** — for each call matching receiver regex `\b_?telemetry\??\.(\w+)\s*\(` in `src/**/*.cs` (excluding `bin/`, `obj/`, and the definition file `src/wa.application/Telemetry/WaTelemetryReporter.cs`), skip calls whose method is FileNameSlot / IpSlot (they ARE the transform). In the balanced-paren argument text: strip string literals, strip `TelemetryEvents.\w+` member accesses, strip slot-wrapped spans (`PiiTransforms.FileName(…)`, `PiiTransforms.IpAddress(…)`, `.FileNameSlot(…)`, `.IpSlot(…)`), then split remaining identifiers into camelCase/underscore words (lower-cased). Any word in PII_WORDS = email, mail, address, name, ip, password, passwd, secret, sas, sig, signature fails. (`cancellationToken` is intentionally not caught: token is not in PII_WORDS.)
  - **R3 server template placeholder** — every `{placeholder}` in a `_logger.Log*("…")` template inside `WaTelemetryReporter.cs` must be in SERVER_PROPS (strip a `:format` suffix before compare). Placeholder outside the set fails; if it also contains a PII word the message says "PII — hash via FileNameSlot/IpSlot (TA-9.4)".
  - **R4 string-slot wrap** — a call to a STRING_SLOT_METHODS member must have its argument begin with `PiiTransforms.` or contain `.FileNameSlot(` / `.IpSlot(`; a bare `request.LinkId` fails.
  - **R5 client props** — for each `trackClientEvent(` call in `src/wa.web/src/**/*.{ts,tsx}` (excluding `*.test.ts(x)`, `__lint-fixtures__/`, and the definition file `core/telemetry/clientTelemetry.ts`): the second argument, if present, must be an object literal (a bare identifier fails: "props must be a literal so the guard can see the keys"). Extract keys: strip `//` and `/* */` comments first; split the top-level object by top-level commas; a segment `^\w+$` is a shorthand key, `^(\w+)\s*:` is an explicit key, a `...` segment is searched for nested `{…}` literals whose keys are extracted the same way. Every key must be in CLIENT_PROPS; R1 applies to the argument text; R2's word check applies to the value expressions (after stripping literals).
  - **R6 bypass** — `TelemetryClient`, `.TrackEvent(` or `.TrackTrace(` anywhere in `src/**/*.cs`, or the ingestion host the App Insights ingestion host (dc.services.visualstudio.com) in any non-test web file other than `core/telemetry/clientTelemetry.ts`, fails ("telemetry must go through the reporter / trackClientEvent — AC-056-4"). This keeps the scanned surface complete.
- **D-4 Negative proof = built-in `selftest` mode**, not fixture files in `src/`. The script's rule functions are pure (text in → findings out); `selftest` runs them over inline seeded snippets and asserts each expected finding, plus clean snippets copied from today's real shapes (`UploadEngine.ts:169` conditional spread, `GetPublicTransferQuery.cs:62`, `StubbleTemplateRenderer.cs:72` `_telemetry?.`, `RecipientStore.ts:410` with its trailing `// TA-7.2:` comment) that must produce zero findings. Exit 1 if any expectation fails. Rationale: no fixture to exclude from scans/lint/tsc, runs in CI on every PR, mirrors the pitfalls rule "prove a new gate fails". Precedent for a seeded-violation proof: `src/wa.web/src/features/errors/__lint-fixtures__/Probe.tsx` + `src/wa.web/src/core/i18n/lintRule.test.ts`.
- **D-5 Wiring:** new job `pii-check` in `.github/workflows/ci.yml`, mirroring `contrast-check` (`.github/workflows/ci.yml:108`): checkout, setup-node 20, `node scripts/check-telemetry-pii.mjs`, `node scripts/check-telemetry-pii.mjs selftest`. Not added to `npm run lint` — the script scans C# too, so it belongs at repo root (same choice as theme-check / contrast-check). AGENT.md §4 gate line is orchestrator close-out (the ci.yml header says job set mirrors §4 1:1).
- **D-6 Scope boundary vs T-069 (F-XCT-005, `docs/Milestone-Backlog.md:145`).** T-069 owns the `[Pii]` attribute, `ErasureScope.AllColumns`, event-DTO convention tests and the general ILogger log-template scan (FR-048-4/5). This task does NOT create a `[Pii]` attribute or scan non-telemetry `_logger` calls. Event DTOs carrying `Pii=true` do not exist yet, so "marked PII" here means: the only sanctioned way a PII-shaped value reaches a property is a TA-9.4 slot transform; anything else fails. Output format: per-file finding lines `path:line  Rn  message`, summary table counts, then `PASS — …` / `FAIL — …` like check-theme-tokens.mjs.

[Fact]
public void StringParameters_AreAClosedSetOfSlots_NoNewRawStringProperty()
{
    var actual = typeof(WaTelemetryReporter)
        .GetMethods(BindingFlags.Public | BindingFlags.Instance | BindingFlags.DeclaredOnly)
        .SelectMany(m => m.GetParameters().Where(p => p.ParameterType == typeof(string)).Select(p => $"{m.Name}.{p.Name}"))

        .ToArray();

}

## 4. Open Questions / Risks

- **Existing raw-PII log templates (outside this task's surface — recorded, not fixed):** `src/wa.application/UseCases/Auth/Signup.cs:86` (`{email}` at Information), `src/wa.application/UseCases/Transfers/SendNotificationEmails.cs:170` (`{Address}` at Error), `src/wa.infrastructure/Persistence/UnsubscribeService.cs:59` (`{Address}` + `{SenderEmail}` at Information). These violate TA-10.5 ("no PII in default level") but are plain `_logger` calls, not event helpers; the general log-template scan is T-069 FR-048-5. Recommend the orchestrator log them against T-069 (or a follow-up gap task) rather than widen T-012-05. Extending R2 to every `_logger` call would fail CI on day one.
- **Regex scanner limits:** it is a paren/quote-aware text scan, not a Roslyn/TS parser; a helper called through an alias variable (e.g. `var t = _telemetry; t.X(...)`) would escape R2. Mitigated by R6 (single exits) and the reflection pin; T-069 can promote to a convention test if it outgrows a script (US-048-02 edge case: "if it outgrows a script, that's an ADR").
- `forgot_password_requested` / `email_failures_1h` templates are scanned for placeholders only (count) — closed-set naming is T-056 / T-012 territory, unchanged here.
- No new packages, no TelemetryEvents change (30), no ProblemCodes change (18), no env vars.
