# T-017-03 Plan — 44 px touch targets + no-hover affordances across P0 surfaces (FR-017-4/5)

**Feature:** F-TRF-017 (Mobile Web) · **Story:** US-017-03 · **Spec:** FR-017-1/4/5, AC-017-3, EC-017-3 · **Size:** M
**Architecture:** TA-8.2 (feature-self-contained styles), TA-8.4 (mobile/perf budgets — F-TRF-017 row), TA-14.1 (static gate + E2E pyramid), TA-17 (no new package).

## 1. Goal

Every interactive element on every P0 surface is ≥ 44 px tall (and never explicitly narrower than 44 px) at a 360 px viewport, inputs use 16 px font, the known 360 px overflow sources wrap, and a new repo-root static gate (`scripts/check-tap-targets.mjs`, chained into `npm run lint`) enforces this. **Exit check:** `npm run lint && npm run test:run && npm run build` green in src/wa.web; `node scripts/check-tap-targets.mjs` prints PASS and exits 1 when one rule is broken on purpose; desktop above 640 px is byte-for-byte unchanged (all new CSS sits inside `@media (max-width: 640px)`).

### 2.2 The gate: `scripts/check-tap-targets.mjs` (decision already taken in the task file)

- **Location:** repo root `scripts/`, like `check-contrast.mjs` / `check-no-positive-tabindex.mjs` (same header-comment style, import.meta.url-relative paths, node built-ins only — TA-17, no package). **Wiring:** `src/wa.web/package.json` `lint` becomes `eslint . && node ../../scripts/check-tap-targets.mjs`. Justification: the task decision says "npm run lint companion"; CI already runs `npm run lint` in two jobs (`.github/workflows/ci.yml:24`, `:79`), so no new CI job is needed and the AGENT.md §4 gate picks it up for free. It stays runnable from repo root (`node scripts/check-tap-targets.mjs`).
- **Static, not layout:** it cannot compute layout; it checks declared CSS. Rules (phone viewport = rules outside any `@media` + rules inside `@media (max-width: Npx)` with N ≥ 360; `prefers-*` / `min-width` media ignored; stylesheet order = `main.tsx` import order: index.css, recipient.css, errorMap.css; last declaration wins per class+property):
  1. **Collect interactive elements** from P0 TSX (non-test, not `__lint-fixtures__`): opening tags `button`, `a`, `input`, `select`, `textarea`, or any tag with `role="button"|"tab"|"menuitem"`. Tag end found by a tiny scanner tracking `{}` depth and quotes (JSX attributes contain `=>`). Block comments stripped first. Classes from `className="..."` or ``className={`...`}`` with `${...}` segments removed (so the template prefix `au-tab` / `mf-pill` / `dz` survives). `input type="file"` / `type="hidden"` exempt (global `input[type='file'] { display:none }`, `index.css` line ~123).
  2. **Height floor (GATE):** per element, max over its classes of last-wins `min-height`/`height` px must be ≥ 44; any class whose last-wins `height` px < 44 also fails.
  3. **Width floor (GATE, explicit only):** fail if a class's last-wins `width` or `min-width` is a px value < 44 and no class gives ≥ 44. Text buttons with no declared width are not checked (content-sized; T-017-04 computed styles cover runtime).
  4. **Font floor (GATE):** `input` (non-file/hidden/checkbox/radio, including expression `type={...}`), `select`, `textarea`: last-wins `font-size` (resolving the fs-* custom properties from `index.css` :root) ≥ 16 px.
  5. **Hover reveal (GATE):** any rule whose selector contains `:hover` and declares `display`, `visibility`, or `opacity: 0` fails (FR-017-5).
  6. **Unclassed interactive element** → fail ("cannot verify — add a class or allowlist").
  7. **ALLOW** map `{ className: reason }`, starting with exactly `dz`. Allowlisted classes satisfy rules 2–3.
- Output: one `relative/path.tsx:line <tag class="..."> reason` line per violation on stderr, exit 1; else `PASS — N interactive elements on P0 surfaces meet the 44 px / 16 px floor (T-017-03).`, exit 0.
- Defense in depth: this gate + T-017-04's Playwright computed-style check (US-017-03 Technical notes).

### 2.3 Tradeoffs
- Fixes are phone-only (task constraint: desktop above 640 px unchanged). The desktop 32/36 px controls remain; UI-Reference §3's floor is stated for touch (F-TRF-017-4).
- Last-wins-per-class ignores selector specificity/ancestor qualifiers; good enough for this flat BEM-ish stylesheet and keeps the script ~150 lines. False passes are caught by T-017-04.

**`scripts/check-tap-targets.mjs`** (CREATE) — skeleton guidance:
- Header comment mirroring `scripts/check-no-positive-tabindex.mjs` (task id, FR-017-4/5, run command, GATE semantics, limitation: static CSS, not layout — T-017-04 owns computed styles).

- CSS parser: strip `/* */`; walk with a depth counter; top-level `@media (...) {` → applicable iff it matches /max-width:\s*(\d+)px/ with N ≥ 360 and has no `min-width`; other at-rules skipped. Each rule: split selector on `,`; a selector targets class C when its last compound (after the final space / `>` / `+` / `~`) is exactly `.C` (no `:` / `[`). Hover rules: any selector containing `:hover`.
- Values: px via /^(\d+(?:\.\d+)?)px$/; var(fs-*) resolved from the index.css `:root` block; anything else (auto, %, dvh) = not a px floor.
- ALLOW: `{ dz: 'drop-zone surface (role=button): >= 44 px from padding + content, not min-height' }`.
- Exit 1 on any violation, else PASS line. Keep it ≤ ~180 lines; no dependencies.

## 5. Open Questions / Risks

- **My Files rows as full-width tap targets** (US-017-03 Edge cases wording): rows are not clickable today; the discrete actions are ≥ 44 px buttons and now get a full-width row on phones. Making the row itself a tap target is new behavior (navigation) — out of scope; flag for T-017-04 / F-TRF-009 owner if required.
- **Static gate limits:** ancestor-qualified selectors are treated as unconditional and specificity is ignored; text buttons without declared width are not width-checked. Runtime truth = T-017-04 Playwright computed styles at 360 px.
- **Sticky reserve margins are tight** (rp 96 px vs ~95 px with a 34 px safe area). Not changed here; T-017-04's box-model check is the arbiter.
- **Admin console** is excluded (not an FR-017-1 surface); its `title=`-only "SuperAdmin only" hints remain.
- No escalations: no package, no limit, no security-shaped change; the gate mechanism decision is pre-made in the task file (orchestrator records it in Open-Decisions Part 3).
