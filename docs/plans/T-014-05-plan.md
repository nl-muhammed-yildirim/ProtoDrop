# T-014-05 plan — Account language select (client-only)

**Task row:** `docs/features/Phase 0-MVP/F-TRF-014/F-TRF-014-i18n.md:89` (US-014-02, AC-014-3; gap task 2026-11-17).
**Governing decision:** `docs/Open-Decisions-and-Constants.md:119` (2026-11-17, user decision) — **client-only**: no schema change, no AppUser column, no API change. The row wording "server-side account locale" and the spec UI note "stored on the account" (`F-TRF-014-i18n.md:55`) are **superseded** by that decision (orchestrator edits the spec row; this plan does not).

## 1. Goal

ProfilePage gets a "Language" select (8 endonyms + "Browser default") that persists the choice to localStorage key 'protoDrop.accountLocale' and switches the whole UI immediately; exit check: vitest proves the select writes/removes the key and calls changeLanguage, a re-imported init still resolves the stored "nl" over a German browser (AC-014-3), and the full wa.web gate is green.

## 2. Design & Decisions

- **D-1 — One owner for the key (deep module, TA-8.5).** The key and the supported set already live in `src/wa.web/src/core/i18n/init.ts:33-36` (read path, T-014-02). The write path goes into the same module as two small exports — `readAccountLocale()` and `setAccountLocale(locale | null)` — plus the `SupportedLocale` type and the ordered SUPPORTED_LOCALES list derived from the `resources` keys. ProfilePage never touches localStorage or the key string. `resolveInitialLanguage()` step 1 is refactored to call `readAccountLocale()` so read and write share one guarded accessor (behavior unchanged; existing detect tests are the regression net).
- **D-2 — `setAccountLocale(null)` = "Browser default".** Removes the key, then changeLanguage to `resolveInitialLanguage()` (now browser → en). `setAccountLocale('nl')` writes the key and changes to `'nl'` directly (`locale ?? resolveInitialLanguage()`), so a blocked-storage browser still switches for the session. Storage access follows the typeof-window + try/catch pattern of `src/wa.web/src/core/auth/session.ts:38-55`.
- **D-3 — Immediate switch needs a re-render.** No component uses react-i18next hooks; every surface calls i18n.t during render (e.g. `src/wa.web/src/features/profile/ProfilePage.tsx:89-110`, `src/wa.web/src/App.tsx:95`). changeLanguage alone repaints nothing. App subscribes once to the i18next 'languageChanged' event and stores the language in state, so the whole tree (no `memo` anywhere in `src/`) re-renders in the new language. Rejected: `location.reload()` (loses in-flight upload state, jsdom-hostile); wrapping in I18nextProvider (larger refactor, out of scope).
- **D-4 — Endonyms live in the bundles (FR-014-2).** Ten new keys, all 3-segment per TA-8.5 (scheme test `src/wa.web/src/core/i18n/init.test.ts:48`): profile.language.label, profile.language.browserDefault, and profile.language.{en,nl,fr,es,pt,it,de,tr}. The eight endonym values are **identical in every bundle** (a language is always shown in its own name); label/browserDefault are translated. Rejected: Intl.DisplayNames (inconsistent casing — "français", "español" — and ICU-dependent test output). Each option carries `lang={code}` so assistive tech pronounces the endonym correctly (WCAG 3.1.2, no cost).
- **D-5 — Styling reuses `.pf-theme-select` (UI-Reference §5.5 pattern).** Same label/select pair as theme (`src/wa.web/src/features/profile/ProfilePage.tsx:97-102`); `.pf-theme-select` already has the ≤640 px 44 px / 16 px rule (`src/wa.web/src/index.css:1524`), so `scripts/check-tap-targets.mjs` passes with **no CSS change** (theme/contrast scripts unaffected; run anyway as part of the gate). Not disabled while saving — there is no network call.
- **D-6 — Sign-out / account delete do NOT clear the key.** Client-only means there is no server copy to re-hydrate from; clearing on sign-out would make a returning signed-in user land in the browser language, i.e. break AC-014-3 on every re-login. The key is therefore a per-browser preference (the trade-off the user accepted). Consequence: a guest on the same browser after sign-out also sees that language — documented in §5. `handleSignOut`/`handleDeleteAccount` (`src/wa.web/src/App.tsx:78-96`) stay untouched.
- **D-7 — No telemetry, no new packages.** No TA-10.2 event exists for a language change; none is added. No npm package (golden rule 1).
