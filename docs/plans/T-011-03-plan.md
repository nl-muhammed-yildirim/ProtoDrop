# T-011-03 — GetOverviewQuery + endpoint 20: cached platform counts, 5-min TTL (FR-011-6)

TASK: T-011-03 overview endpoint — GET /api/v1/admin/overview (TA-4.2#20): four aggregates cached 5 min in-memory (no Redis — ADR-008), plus the last-20 recent-transfers list and a snapshot timestamp; thin endpoint gated by T-011-01's RequireAdminAsync (superadminOnly:false).
GOAL: AC-011-1 server half — four numbers + recent list returned; second call within 5 min returns the cached snapshot (same timestamp); staleness never exceeds 5 min (FR-011-6); "new users today" is a UTC calendar day.

## ASSUMPTIONS / DECISION
- DECISION: cache = Caches.cs idiom (Entry? + injected clock, singleton), not IMemoryCache — wa.application has no Caching.Memory package reference; fake-clock testable; per-instance is correct per ADR-008.
- DECISION: storage used uses Status IN (1,3) — mirrors T-010-04's metering predicate so the overview matches what F-TRF-007 counts as in-use blobs (DownloadLimit transfers still serve files); the active-transfers card stays Status=1 per FR-011-2's literal.
- DECISION: new users today counts ALL AppUser created in the UTC day regardless of DeletedAtUtc — a signup is a signup.
- DECISION: email sent counted from EmailRecipient.NotifiedAtUtc (the spec-named approximation); failed from DomainEvent rows with EventType 'email.failed' — no DLQ table exists; both stated verbatim in the query's summary comment.
- DECISION: recent-list owner email = AppUser.Email joined via OwnerAppUserId, else null (no SenderEmail fallback).
