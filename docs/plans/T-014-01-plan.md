# T-014-01 — i18next init + 8 locale resource bundles (TA-8.5)

TASK: T-014-01 i18next init + 8 locale resource bundles (milestone task T-026, F-TRF-014, TA-8.5). Branch feature/F-TRF-014.
GOAL: first real i18next resource bundles at core/i18n/locales/{lang}.json for en, nl, fr, es, pt, it, de, tr (FR-014-1); t() available in components via react-i18next with fallback language en; a stub resolver returns en (T-014-02 replaces it). No string sweep — that is T-014-03.

## KEY REPO FACTS (verified against live source 2026-11-10 — trust over plan prose)
- i18next and react-i18next are NOT in src/wa.web/package.json yet (deps: @azure/storage-blob, react, react-dom, zustand; devDeps include vitest ^3.2.7). Installing them is the only new-package step of this task — ADR line required (TA-17 / AGENT.md §3 rule 1), recorded per the T-012-02 precedent in docs/Open-Decisions-and-Constants.md Part 3.
- Existing client copy is translation-key constants, not bundles: src/wa.web/src/core/i18n/keys.ts holds DEGRADED_COPY (T-013-04) with uploadDegraded and downloadUnavailable values — English source-of-truth for the seed keys. Do NOT sweep components to t() in this task.
- src/wa.web/src/main.tsx imports index.css, recipient.css, errorMap.css then renders App — i18next init must run before that render (importing the init module at the top of main.tsx is sufficient; it runs synchronously on import).
- wa.web gates: npm run lint && npm run test:run && npx tsc -b (build = tsc -b && vite build). test:run is non-watch vitest; bare vitest enters watch mode and hangs.
- The repo's vitest jsdom environment has NO window.localStorage (only sessionStorage) — guard storage access for SSR/test safety, committed pattern in src/wa.web/src/core/auth/session.ts (typeof-window guard + try/catch).
- C# side untouched: no .cs or .csproj changes; the per-task fast gates dotnet test tests/wa.domain.unit and tests/wa.application.unit just compile.

## DESIGN & DECISIONS
- Static imports of all 8 JSON bundles in init.ts (no dynamic import(), no i18next-http-backend): the files are tiny, TA-8.4 budget stays green, and T-014-02's detection order only swaps which preloaded bundle is active — no loader plumbing needed.
- Stub resolver: a named export resolveInitialLanguage() in init.ts returning 'en' with a comment marking it as the T-014-02 replacement point. No localStorage read yet (the repo jsdom env lacks window.localStorage; real detection lands in T-014-02).
- i18next config: fallbackLng 'en', lng from the stub resolver, interpolation escapeValue false (React escapes), and a dev-only missingKey handler that console.warns key + locale (TA-8.5 / EC-014-1 half of AC-014-2; the translation_missing telemetry wiring belongs to T-014-03's sweep).
- Seed keys: exactly the two DEGRADED_COPY values, so T-014-03 has real keys to wire. Scheme area.screen.control (TA-8.5): landing.dropzone.uploadDegraded and recipient.download.unavailable — all 8 locales carry both keys; en is source-of-truth verbatim from keys.ts.
- ADR: append one row to docs/Open-Decisions-and-Constants.md Part 3 recording i18next + react-i18next (TA-8.1 stack, F-TRF-014) — the T-012-02 precedent for npm-package ADR lines.

## IMPLEMENTATION PLAN
1. cd src/wa.web; npm install i18next react-i18next (latest stable).
2. Create core/i18n/locales/{en,nl,fr,es,pt,it,de,tr}.json — 8 files, identical key set, {area}.{screen}.{control} keys only.
3. Create core/i18n/init.ts: import all 8 bundles; resolveInitialLanguage() stub returning 'en'; i18next.createInstance + init with resources keyed by locale (each bundle under its lng's translation namespace), fallbackLng en, lng from the stub; export the instance as default.
4. Create core/i18n/index.ts barrel re-exporting init so main.tsx imports stay one line.
5. Modify src/wa.web/src/main.tsx: import './core/i18n' (or init) above the createRoot render — before first render.
6. Create core/i18n/init.test.ts (vitest, colocated): 8 files exist; every non-en bundle's key set equals en's; all keys match the 3-segment scheme; t() returns English for a seed key; switching lng to de returns the German value; missing key in a non-en locale falls back to en (never blank).
7. Append the ADR row to docs/Open-Decisions-and-Constants.md Part 3.
8. Gates: cd src/wa.web && npm run lint && npm run test:run && npx tsc -b; plus dotnet test tests/wa.domain.unit and tests/wa.application.unit (compile-only pass).

## TESTS
- init.test.ts covers the exit checks directly: 8 bundles load without errors, key-set parity across locales, scheme shape, fallback en, stub resolver returns en. No component-level t() usage yet — that is T-014-03's sweep.
