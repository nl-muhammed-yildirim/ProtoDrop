# T-017-01 plan — Mobile upload surface: file input + sticky Send.

**Task file:** `docs/features/Phase 0-MVP/F-TRF-017/US-017-01-mobile-upload/T-017-01-mobile-upload-ui.md`
**Spec:** FR-017-2, FR-017-4, FR-017-5, AC-017-1, EC-017-1 | UI-Reference §3, §4.1, §5.1 | TA-8.3 (UploadEngine unchanged), TA-8.4
**Scope:** wa.web only. No new packages. No UploadEngine change.

## 1. Goal

At ≤ 640 px the landing/upload surface is single column with a visible **Choose files** button, a viewport-pinned bottom bar holding the overall progress line above **Send.**, and staging rows whose remove control is a visible ≥ 44 px tap target with truncated names and visible sizes — exit check: the task file's five boxes, encoded by vitest markup + CSS-contract tests (manual/iPhone e2e is T-017-04's matrix).

## 2. Design & Decisions

**What already holds (no change needed — grounded in source):**
- **Choose files** button is always rendered and visible (`src/wa.web/src/features/landing/DropZone.tsx:121-125`); the zone itself is click-to-browse (`DropZone.tsx:105`), so it is never drag-only (FR-017-2, UI-Reference §4.1).
- The file input is `type="file" multiple` (`DropZone.tsx:126-133`), staging accumulates across picks via `addFiles` (`src/wa.web/src/core/upload/UploadEngine.ts:191-199`), and Send goes through the same `useUploadEngine.start` (`src/wa.web/src/features/landing/StagingList.tsx:161`) — TA-8.3, no mobile pipeline.
- `.sl-remove` is always rendered (not hover-revealed) with `min-width/min-height: 44px` (`src/wa.web/src/index.css:194-206`); `.sl-name` already truncates with ellipsis and `title` (`index.css:180-185`, `StagingList.tsx` row), `.sl-size` is `nowrap`.
- The upload surface has **no visible form field**: the input is `display: none` (`index.css:119-121`), and the button is `.btn-primary` (`min-height: 44px`, `font-size: var(--fs-body)` = 16 px, `index.css:97-107`). Instruction 5 (44 px / 16 px inputs) is therefore already satisfied — nothing to add.
- The existing window paste handler (`DropZone.tsx:64-75`) is the F-TRF-001 desktop Ctrl/Cmd+V path; EC-017-1 needs no new code (a share-sheet image arrives through the file input's `onChange` like any picked file). We add **no** global paste handler and do not touch the existing one.

**D-1 — `accept` attribute: do NOT add `accept="image/*"` (escalated, see §5).** `accept="image/*"` filters the picker to images on Android Chrome (image/camera picker only) and desktop browsers (Image Files filter; macOS greys out other types), and restricts the iOS "Choose File" (Files) branch to images — contradicting FR-001-1 / US-017-01 ("camera, Photos, Files") any-file upload. A plain `<input type=file multiple>` on iOS Safari already offers Photo Library / Take Photo / Choose File, so FR-017-2's "camera/Photos on iOS" holds without it. The plan keeps the input as-is and adds a unit test pinning "no `accept`, still `multiple`". If the orchestrator/human picks the task file's option instead, the delta is one attribute plus flipping that one assertion.

**D-2 — sticky bar = the existing `.sl-footer`, with `.sl-overall` moved inside it (one element, two positions — EC-016-3 precedent, `src/wa.web/src/features/recipient/recipient.css:244-260`).** FR-017-5 wants the overall progress line directly above the sticky Send. Two separately fixed elements would need a hand-computed offset (fragile with safe-area insets); a duplicated mobile-only line would double the `role="status"` live region (F-TRF-016-3). So the `<p className="sl-overall" role="status">` moves from above the list into `.sl-footer`, before `.sl-send-wrap`. Tradeoff: on desktop the overall line now sits under the total line, directly above Send — still consistent with UI-Reference §5.1 ("footer row: Send."), and no e2e selects `.sl-overall` positionally (grep: only `ariaLive.spec.ts`/`keyboard.spec.ts` use `role="status"` closest-lookups, which still match). Focus order unchanged (a `<p>` is not focusable; `keyboard.spec.ts:33` stop list unaffected).

**D-3 — mobile CSS in one `@media (max-width: 640px)` block in `src/wa.web/src/index.css`** (landing styles live there; T-003-08 pattern, `recipient.css:245-276`):
- `.dz`: `min-height: auto; width: calc(100% - 32px); padding: 32px 16px;` and `.dz-title { font-size: var(--fs-h1); }` (40 px display line overflows 360 px).
- `.sl`: `padding: 0 16px 136px;` — reserved bottom space so the pinned bar never covers the last row / total / limit message (overall line ≈ 20 px + margin 12 + button 44 + padding 16 + safe-area).
- `.sl-footer`: `position: fixed; left: 8px; right: 8px; bottom: 0;` (exactly two horizontal constraints — pitfalls), `padding: 8px 8px calc(8px + env(safe-area-inset-bottom, 0px)); background: var(--bg); border-top: 1px solid var(--border); display: flex; flex-direction: column; gap: 8px;` — opaque `--bg` so the page scrolls under it (TA-8.4). `.sl-overall { margin: 0; }` inside it.
- `.sl-send-wrap { display: block; } .sl-send { width: 100%; }`.
- `.sl-row { flex-wrap: wrap; } .sl-name { min-width: 0; }` — a failed row's message + Retry wrap to a second line instead of pushing `.sl-remove` out of the `overflow: hidden` row at 360 px.
- `.sl-retry { min-height: 44px; }` (FR-017-4, it is a staging-row control).
- `touch-action: manipulation` on `.dz-button, .sl-remove, .sl-retry, .sl-send` (T-003-08 precedent; no hover affordance added).
Only existing tokens (`--bg`, `--border` in `src/wa.web/src/styles/tokens.css:7,16`; `--fs-h1` in index.css :root) — no new token, theme/contrast gates unaffected. Note: verify_plan.py reads only index.css :root, so it reports the three color tokens (incl. `--fg-muted`, tokens.css:11) as missing — a known tool staleness since T-015-01 moved colors to tokens.css, not plan drift.

**D-4 — tests:** jsdom applies no media queries, so the CSS is pinned by a CSS-contract unit test that reads `index.css` with `readFileSync` + `fileURLToPath` (precedent `src/wa.web/src/features/recipient/recipientRoute.test.ts:1-14`). Markup changes are pinned in the existing `StagingList.test.tsx` / `DropZone.test.tsx`. No e2e added — T-017-04 owns the Playwright mobile matrix (`src/wa.web/e2e/mobile.spec.ts` today covers only the recipient page).

## 5. Open Questions / Risks

- **ESCALATION (D-1):** the task file's pre-made DECISION (`accept="image/*"`) would restrict non-image uploads on Android and desktop and narrow the iOS Files branch, contradicting FR-001-1 / US-017-01. The plan implements the non-restricting option and pins it with a test; the orchestrator surfaces the DECISION block and records the outcome in Open-Decisions Part 3. If option A is chosen, the Coder adds `accept="image/*"` to `DropZone.tsx:126-133` and inverts the step-4 assertion.
- **Desktop layout shift (D-2):** the overall progress line moves from above the list to above Send on desktop too. Low risk (no positional selectors); if the reviewer objects, the fallback is desktop `order` via a flex `.sl` — more CSS for no user value.
- **Reserved padding value (136 px)** is an estimate; a long limit message on two lines still sits inside `.sl` above the padding, so it stays visible. Visual check in step 6.
- iPhone real-device behavior (Photos/camera sheet, share-sheet paste — EC-017-1) cannot be unit-tested; it is T-017-04's real-device spot check.
