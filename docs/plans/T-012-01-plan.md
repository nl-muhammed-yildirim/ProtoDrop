# T-012-01 — Worker + browser traceparent (TA-10.1, FR-056-1)

TASK: T-012-01 Worker + browser traceparent: workers read/generate W3C traceparent; browser attaches one per page load (AC-2); zip trigger passes it through
GOAL: every f-* worker surfaces a valid W3C traceparent in its logs (reads inbound header, generates when absent — EC-056-1), the browser attaches a valid traceparent to every API fetch (same id for one page load), and the API→f-zip trigger forwards the request's traceparent so zip logs share the caller's correlationId. Exit check: grep any worker log line → valid W3C traceparent present; browser DevTools → header on requests; App Insights (manual) → same 8-hex id across API + worker for one flow.

## KEY REPO FACTS (verified against live source 2026-11-05 — trust over plan prose)
- `W3CTraceParser` (`src/wa.domain/Correlation/W3CTraceParser.cs`) already exists: static class, `Parse(string?) → TraceParent?`, `ParseTraceId`, `NewTraceId()` (Guid "n" = 32 lowercase hex), `SupportedVersion = "00"`. Malformed/wrong-version/all-zero → null (EC-056-1). `wa.domain` is referenced by wa.workers via wa.infrastructure — no new project reference needed.
- `TraceParent` record (`W3CTraceParser.cs` L43): `(Version, TraceId, ParentId, Flags)`, `.ToHeader()`, `.CorrelationId => TraceId[..8]`.
- API half is DONE (T-011-era FR-056-1): `src/wa.api/Middleware/CorrelationMiddleware.cs` — parses/generates, `CorrelationContext.Set(...)`, Serilog `LogContext.PushProperty("CorrelationId"|"TraceParent")`, echoes header on the response. Registered at Program.cs L164 (before everything).
- `CorrelationContext` (`src/wa.domain/Correlation/CorrelationContext.cs`) is AsyncLocal — ambient within one process only; it does NOT cross a fire-and-forget HTTP call or a process boundary. The zip trigger must pass the header explicitly.
- Zip trigger: `GetDownloadAllUrlHandler.TriggerZipGeneration` (`src/wa.application/UseCases/Transfers/GetDownloadAllUrlQuery.cs` L124) — builds POST `{baseUrl}/zip/{transferId:n}` with only `x-zip-sign`. Add the traceparent header here; read it from `CorrelationContext.CurrentRequest?.ToHeader()`.
- Workers: single project src/wa.workers, 5 functions — ZipFunction.cs, ExpireFunction.cs, DeleteTransfersFunction.cs, DeleteBlobsFunction.cs, EmailFunction.cs. Logging is Microsoft.Extensions.Logging (ILogger<T> ctor-injected); NO Serilog in wa.workers (csproj has no Serilog refs). No traceparent handling anywhere yet.
- `ZipFunction.Run` reads headers via `req.Headers.GetValues("x-zip-sign")` idiom (L56) — the same API is used for the new header read.
- f-expire envelope: `ExpireTransfersHandler` (`src/wa.application/UseCases/Transfers/ExpireTransfers.cs` L66) sets `CorrelationId = Guid.NewGuid()` with comment "background job — no W3C trace context". This task's scope is worker LOGS + browser + zip trigger; the envelope field stays as-is (it's a separate Guid-typed column, not the header).
- Browser: NO shared fetch client — 32 `fetch(` calls across ~18 files in src/wa.web/src/ (App.tsx, features/auth/AuthPage.tsx, ...). All target the same API base (per-file constants like AuthPage's API_BASE).
- Test projects: tests/wa.domain.unit (has Correlation/W3CTraceParserTests.cs), tests/wa.application.unit, tests/wa.api.integration (Testcontainers + Docker), tests/wa.workers.unit (exists; hand stubs, no Moq). Web: vitest (`npm run test`) — existing *.test.tsx files per feature.

## ASSUMPTIONS / DECISION
- Workers use MEL BeginScope (not Serilog LogContext) because wa.workers has no Serilog dependency. The scope keys "CorrelationId"/"TraceParent" match the API's Serilog property names so App Insights can group on both surfaces. If a reviewer wants Serilog in workers, that's a separate infra task — not this one.
- Browser mints ONE traceparent per page load (memoized module state), not per request: same user action chain = same id, which is what makes the DevTools/App Insights check meaningful. A refresh mints a new one (new SPA lifetime).
- f-expire/f-delete-* envelopes keep their Guid CorrelationId field untouched — that's the event-stream correlation (TA-5.1), distinct from W3C trace context; this task only adds the header to logs.
- Zip trigger reads `CorrelationContext.CurrentRequest` inside TriggerZipGeneration: Task.Run inherits AsyncLocal, and the handler runs on the request path where CorrelationMiddleware has set it — verified against Program.cs L164 + GetDownloadAllUrlQuery L114.
