|---|---|---|
| `chromium` | `{ browserName: 'chromium' }` (identical to today's default) | everything EXCEPT `mobile.spec.ts` (testIgnore) |
| `mobile-iphone-14` | `devices['iPhone 14']` → WebKit, 390×664, isMobile, hasTouch | only `mobile.spec.ts` (testMatch) |

### D-3 — AC-017-3 / EC-017-3 assertions live in one helper module
New `src/wa.web/e2e/mobile-helpers.ts` (single consumer today, but keeps the spec readable; deep module: one call per screen):
- `expectPhoneLayout(page, screen)` — at the current viewport: `document.documentElement.scrollWidth <= window.innerWidth`; then every VISIBLE interactive element (`a[href], button, input:not([type="hidden"]), select, textarea, [role="button"], [tabindex]:not([tabindex="-1"])`) must have a bounding box ≥ 44 × 44 (0.5 px subpixel tolerance) and input/select/textarea computed font-size ≥ 16 px (T-017-03's static rule 3, now at runtime). "Visible" excludes: computed display none / visibility hidden, a box ≤ 1 px in either axis (visually-hidden / sr-only clip), and boxes entirely outside `[0, innerWidth]` horizontally. Failures are collected as `tag.class WxH` strings and asserted with `toEqual([])` plus the screen label — one readable diff per screen. Probed during planning on `/` and `/account` at 360 px in both engines: all targets exactly 44 px tall, scrollWidth 360 — the assertion is satisfiable and tight.
- `expectStickyClear(page, lastSelector, barSelector)` — scrolls to the bottom and asserts the last row's bottom ≤ the fixed bar's top (T-017-03 flagged the `.rp` 96 px / `.sl` 136 px reserves as "verified by T-017-04", `docs/plans/T-017-03-plan.md:39`).
- `expectViewportMetaScalable(page)` — `meta[name=viewport]` content exists, contains `width=device-width`, and matches neither `user-scalable\s*=\s*(no|0)` nor `maximum-scale\s*=\s*1(\.0*)?\b` (today: `width=device-width, initial-scale=1.0`, `src/wa.web/index.html:6`).
- `expectZoomSafe(page, screen)` — **200 % zoom, deterministic definition:** the same page laid out in half the CSS width (360 → 180 px, page.setViewportSize; deviceScaleFactor untouched) = what 200 % browser zoom produces. Asserts no horizontal scroll and that body/h1 computed user-select is not `none` (text selectable), then restores 360 × 780. Probed: `/` gives scrollWidth 180 at 180 px in both engines. 44 px is NOT re-checked at 180 (targets scale with zoom).
- `buildStoredZip(entries)` — ~35-line stored (method 0) zip writer using node:zlib's crc32 (Node 26.8.1 here; the function exists since Node 22.2, typed in @types/node 24). No package.

```ts
import zlib from 'node:zlib'

/** Stored (no compression) zip with UTF-8 names (general-purpose flag bit 11). Enough for a byte-identity download check. */
export function buildStoredZip(entries: Array<{ name: string; data: Buffer }>): Buffer {
  const locals: Buffer[] = []
  const centrals: Buffer[] = []
  let offset = 0
  for (const e of entries) {
    const name = Buffer.from(e.name, 'utf8')
    const crc = zlib.crc32(e.data) >>> 0
    const lh = Buffer.alloc(30)
    lh.writeUInt32LE(0x04034b50, 0); lh.writeUInt16LE(20, 4); lh.writeUInt16LE(0x0800, 6); lh.writeUInt16LE(0, 8)
    lh.writeUInt16LE(0, 10); lh.writeUInt16LE(0x21, 12) // 00:00, 1980-01-01
    lh.writeUInt32LE(crc, 14); lh.writeUInt32LE(e.data.length, 18); lh.writeUInt32LE(e.data.length, 22)
    lh.writeUInt16LE(name.length, 26); lh.writeUInt16LE(0, 28)
    const ch = Buffer.alloc(46)
    ch.writeUInt32LE(0x02014b50, 0); ch.writeUInt16LE(20, 4); ch.writeUInt16LE(20, 6); ch.writeUInt16LE(0x0800, 8)
    ch.writeUInt16LE(0, 10); ch.writeUInt16LE(0, 12); ch.writeUInt16LE(0x21, 14)
    ch.writeUInt32LE(crc, 16); ch.writeUInt32LE(e.data.length, 20); ch.writeUInt32LE(e.data.length, 24)
    ch.writeUInt16LE(name.length, 28) // extra, comment, disk, attrs stay 0
    ch.writeUInt32LE(offset, 42)
    locals.push(lh, name, e.data)
    centrals.push(ch, name)
    offset += lh.length + name.length + e.data.length
  }
  const cd = Buffer.concat(centrals)
  const eocd = Buffer.alloc(22)
  eocd.writeUInt32LE(0x06054b50, 0); eocd.writeUInt16LE(entries.length, 8); eocd.writeUInt16LE(entries.length, 10)
  eocd.writeUInt32LE(cd.length, 12); eocd.writeUInt32LE(offset, 16)
  return Buffer.concat([...locals, cd, eocd])
}
```

- **180 px zoom step on recipient rows / My Files** is not probed (stack was down during planning). A real overflow is handled per D-6; a structural one becomes a DECISION.
- **Staging (T-028):** suite is local-only (hard-coded API base, Azurite dev-key seeding). Running it against staging needs an env-driven baseURL + an API-only seeding path — T-028 scope; any new env var escalates there. Real-device check is manual (QA-SCRIPTS S-5.3, orchestrator).
- **My Files owner attribution** relies on page.request carrying the injected `wa.session` cookie to `:8080`; if the row does not appear, the empty state is still swept (layout check holds) — note it rather than reworking auth.
- Download-all mints count against the transfer's download cap (`GetDownloadAllUrlQuery.cs:109`); every test seeds its own transfer, so no cross-test coupling.
