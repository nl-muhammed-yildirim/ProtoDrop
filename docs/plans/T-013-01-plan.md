TASK: T-013-01 Error mapper guarantee + dev injected-failure endpoint
GOAL: Guarantee that every unhandled exception through the pipeline yields a 500 Problem+JSON with code INTERNAL and correlationId (TA-4.1.3 closed list), and add a dev-only GET /api/v1/dev/chaos?kind=internal|rate_limited endpoint so E2E can force both failure shapes without prod surface (FR-013-2, FR-013-6).

## KEY REPO FACTS (verified against live source 2026-11-09)
- Pipeline order in src/wa.api/Program.cs: CorrelationMiddleware → UseIpRateLimiting → IdempotencyMiddleware → SessionMiddleware → GlobalErrorMiddleware → SerilogRequestLogging → routes. GlobalErrorMiddleware sits after all business middleware so it catches every unhandled exception (L170).
- GlobalErrorMiddleware (src/wa.api/Middleware/GlobalErrorMiddleware.cs): catches BusinessException → its closed-list code + status; catches any other Exception → 500 INTERNAL via ProblemWriter.WriteCompleteAsync. Logs the full stack to Serilog (TA-10.5: stack stays in logs, out of body).
- ProblemWriter (src/wa.api/Middleware/ProblemWriter.cs): single construction site for TA-4.1.3 shape — type, title, status, code, details, optional errors[], correlationId (exact key order; JsonObject preserves insertion order). correlationId comes from CorrelationContext (first 8 hex of W3C trace-id, stamped by CorrelationMiddleware).
- ProblemCodes (src/wa.domain/Errors/ProblemCodes.cs): 18 members — the closed TA-4.1.3 machine-code list. At M0 only NOT_FOUND, INTERNAL and RATE_LIMITED are exercised by the pipeline; the rest are pinned for future endpoints.
- Rate limiting: AspNetCoreRateLimit 5.0.0 (ADR T-056-03), rule *:/api/v1/auth/* = 5/min per IP → 429 RATE_LIMITED + Retry-After via ProblemWriter (Program.cs L104–116). The chaos endpoint's rate_limited kind writes the same shape directly without consuming a limiter slot.
- No existing dev-only route in Program.cs at HEAD — no IsDevelopment guard, no /dev/ prefix anywhere in src/.
- Integration tests use WebApplicationFactory (tests/wa.api.integration/PipelineTests.cs pattern): test host defaults to EnvironmentName = "Development", so an IsDevelopment()-gated route IS visible to integration tests but absent from prod.

## ERROR CODES
- INTERNAL (500) — triggered by kind=internal: plain InvalidOperationException thrown in the handler, caught by GlobalErrorMiddleware, mapped to 500 INTERNAL via ProblemWriter. Same code as every other unhandled exception (TA-4.1.3 closed list).
- RATE_LIMITED (429) — triggered by kind=rate_limited: written directly via ProblemWriter.WriteCompleteAsync with status 429 and code RATE_LIMITED. Identical shape to the real AspNetCoreRateLimit breach path (Program.cs L115).

## ASSUMPTIONS / DECISIONS
- **DECISION:** chaos route — TA-4.2 catalog lists no chaos route; add GET /api/v1/dev/chaos with kind=internal|rate_limited, gated to the Development environment via app.Environment.IsDevelopment() (same idiom as launchSettings.json ASPNETCORE_ENVIRONMENT). If review objects to an unlisted route it surfaces as ESCALATION per AGENT.md §8 rather than adding prod surface.
- **Assumption:** rate_limited kind writes the 429 directly via ProblemWriter rather than triggering AspNetCoreRateLimit — keeps the chaos endpoint self-contained, avoids consuming a slot in the auth limiter's 5/min window during E2E runs, and produces byte-identical output (same writer, same code, same details text).
- **Assumption:** WebApplicationFactory test host defaults to EnvironmentName = "Development" (Microsoft.AspNetCore.Mvc.Testing behavior), so IsDevelopment()-gated routes are visible in integration tests without explicit UseSetting. Verified by the existing PipelineTests pattern which exercises all middleware without environment overrides.
- **Assumption:** no new package needed — the chaos endpoint uses only ProblemWriter, ProblemCodes, and BusinessException already referenced by Program.cs. The InvalidOperationException for kind=internal is BCL.
