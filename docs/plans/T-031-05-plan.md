# T-031-05 Plan — Feature availability follows my plan (US-018-05)

**Feature:** F-BIL-001 (Plan Catalog) · **Story:** US-018-05 · **Milestone row:** T-031 (sub-task 05 of 5) · **Spec:** FR-018-1 (feature toggles per plan), FR-018-2 (no code branches on plan identity), US-018-05 happy path 1–3 + alternative flows + edge cases · **Size:** S
**Architecture:** TA-3.4 (one resolver over PlansCache + FlagsCache, 30 s TTL), TA-13.2 (feature.* gate keys, seeded false), TA-0.2 rule 7 (ports/adapters unchanged), TA-14.3 (Testcontainers SQL). Golden rules 2 and 7.

## 1. Goal

One resolver, `IFeaturesProvider.Resolve(planCode)`, turns a plan row's FeaturesJson into a `PlanFeatures` value with the global `feature.*` kill-switch applied, and a guard test makes it the only backend reader of FeaturesJson and of the five plan-feature gate keys. **Exit check:** dotnet test on tests/wa.domain.unit and tests/wa.application.unit green, plus the filtered integration run of step 5 green (Docker running).

## 2. Design & Decisions

### What exists vs what is missing (grounded at plan time)
- `PlanFeatures` POCO with the five keys (`src/wa.domain/PlanFeatures.cs:6-22`, `sso_scim` maps to `SsoScim`); PlanDefinition validates the key set on write (`src/wa.domain/PlanDefinition.cs:135-144`). Seeds: Free all false, Pro scheduling/analytics/branding true, Business adds sso_scim (`src/wa.infrastructure/Persistence/EntityConfigurations/PlanConfiguration.cs:31,37,42`) — matches Open-Decisions Part 2.
- Global gates are seeded rows `feature.ads|analytics|branding|scheduling|ssoScim` (and seven non-plan gates), all with Value "false" (`FeatureFlagConfiguration.cs:25-36`, `Gate()` at line 82) — TA-13.2 "seeded with default false".
- **No reader exists.** Nothing in `src/` deserializes FeaturesJson or reads a `feature.*` row (grep at plan time: only the validator and the seed touch them; FR-053-3 says gates are "read separately" and LimitsProvider skips them, `src/wa.application/Limits/LimitsProvider.cs:34-38`). No PlanContext middleware yet (F-BIL-003, US-020-01) and no gated feature (F-PRF-001…004) exists. So the answer to "is there an IFeatureAccess today?" is no — this task creates the single seam.

### D-1 — `IFeaturesProvider` in wa.application/Limits, twin of ILimitsProvider (TA-3.4)
New `src/wa.application/Limits/FeaturesProvider.cs` with interface + sealed class, constructor `(PlansCache plans, FlagsCache flags)` — the same caches LimitsProvider uses, so the 30 s TTL (US-018-05 "plan switch … 30 s cache") and "every read through the caches" (FR-053-4) hold with no new cache.
`Task<PlanFeatures> Resolve(string? planCode, CancellationToken cancellationToken = default)`:
1. null/blank → `Plan.DefaultCode` (same rule as `LimitsProvider.cs:28`; guests = Free).
2. `plans.GetAsync(code)` — PlanUnknownException / DB failure propagate unchanged (same contract as limits; EC-018-3 mapping is not this task's).
3. `JsonSerializer.Deserialize<PlanFeatures>(plan.FeaturesJson)` → fresh instance per call (callers cannot mutate a cached value); null → InvalidOperationException naming the plan.
4. Global gate, AND semantics: for each bool property of PlanFeatures, key = `"feature." + JsonNamingPolicy.CamelCase.ConvertName(property.Name)` → feature.ads, feature.scheduling, feature.analytics, feature.branding, feature.ssoScim (exactly the TA-13.2 names; no per-key literals). If the row exists and its value does not parse as `true` (bool.TryParse), the field is forced false. A gate row can only switch a feature **off**; it never grants a feature the plan row lacks.
Deep-module check (codebase-design): small interface (one method, one POCO out), hides JSON parsing, key derivation and precedence; callers (PlanContext in US-020-01, then F-PRF-*) never see FeaturesJson or flag keys. Dependency rule: application → domain only.

### D-2 — Precedence and edge semantics (from the spec, no new decision)
- "Global flag beats plan row — operator escape hatch" (US-018-05 alt flow, US-020-04 edge) + the ads rule "Features.ads AND global feature.ads" (US-020-04 alt flow) ⇒ effective = plan row AND gate, uniformly for all five.
- Consequence to state plainly: every gate is seeded "false", so **today every plan resolves to all-false** — consistent with TA-13.2 and D-14 (gated features are not built; the operator flips feature.scheduling etc. when F-PRF-* ships). No seed is changed.
- Gate row absent → plan row decides (absence is "no kill-switch", not "killed"); the integration test proves all five rows are seeded, so absence is only a hand-deleted row. Gate value garbled (e.g. "yes") → off (a kill-switch fails closed).
- `limits.<plan>.ads|analytics|branding|scheduling|ssoScim` rows are seeded (`FeatureFlagConfiguration.cs:38-77`) but US-018-05 names only two sources (FeaturesJson + global feature.*). They stay ignored here (pinned by a unit test) — see Open Questions.

### D-3 — One read site, enforced by a guard test (US-018-05 happy path 2, technical notes)

### D-4 — Wiring: API only
Register `IFeaturesProvider` as a singleton in `src/wa.api/Program.cs` next to ILimitsProvider (line 96). Workers do not gate features today — `src/wa.workers/WorkerServices.cs` untouched.

### D-5 — What US-018-05's UI ACs need that is not here
"Schedule control disabled with 'Pro plan required'", "no analytics panel is queried", "upgrade → available without reload" require PlanContext (US-020-01: user → plan), the gated features (F-PRF-001…004) and the gated-control UI (US-020-04). This task delivers and proves the data rule those read: Free row → scheduling/analytics off; Pro row + gate on → on; row or gate edit visible after the TTL with no deploy.   
   ```csharp
   public interface IFeaturesProvider
   {
       /// <summary>TA-13.2 global gate key prefix; the segment is the camelCase PlanFeatures property name.</summary>
       public const string GlobalGatePrefix = "feature.";
       Task<PlanFeatures> Resolve(string? planCode, CancellationToken cancellationToken = default);
   }

   public sealed class FeaturesProvider(PlansCache plans, FlagsCache flags) : IFeaturesProvider
   {
       private static readonly (PropertyInfo Field, string GateKey)[] Gates = typeof(PlanFeatures)
           .GetProperties(BindingFlags.Public | BindingFlags.Instance)
           .Where(p => p.PropertyType == typeof(bool))
           .Select(p => (p, IFeaturesProvider.GlobalGatePrefix + JsonNamingPolicy.CamelCase.ConvertName(p.Name)))
           .ToArray();

       /// <summary>The five global gate keys this resolver reads (feature.ads … feature.ssoScim).</summary>
       public static IReadOnlyList<string> GlobalGateKeys { get; } = Gates.Select(g => g.GateKey).ToArray();

       public async Task<PlanFeatures> Resolve(string? planCode, CancellationToken cancellationToken)
       {
           var code = string.IsNullOrWhiteSpace(planCode) ? Plan.DefaultCode : planCode;
           var plan = await plans.GetAsync(code, cancellationToken);
           var features = JsonSerializer.Deserialize<PlanFeatures>(plan.FeaturesJson)
               ?? throw new InvalidOperationException($"Plan '{code}' has no seeded FeaturesJson.");
           var rows = await flags.GetAllAsync(cancellationToken);
           foreach (var (field, gateKey) in Gates)
           {
               var gate = rows.FirstOrDefault(r => string.Equals(r.Key, gateKey, StringComparison.Ordinal));
               if (gate is null) continue; // no kill-switch row → plan row decides
               if (!(bool.TryParse(gate.Value, out var on) && on)) field.SetValue(features, false); // gate only switches off
           }
           return features;
       }
   }
   ```

## 4. Open Questions / Risks

- **Per-plan feature override rows (non-blocking, no DECISION).** `limits.<plan>.ads|analytics|branding|scheduling|ssoScim` are seeded (`FeatureFlagConfiguration.cs:38-77`) and editable on the admin flags page, but no spec says what they do; this plan ignores them (pinned by `Resolve_LimitsPrefixedFeatureKeys_Ignored`). If they should override FeaturesJson like limits keys do (FR-053-2), it is a one-loop change in FeaturesProvider in a later task. Flag for the orchestrator / PO.
- **Story text vs frozen seed on ads.** US-018-05 happy path 1 says Free `ads=true`; Part 2 and the seed say Free ADS false (D-14). The seed (frozen, Part 2) wins; no seed change. The effective result is the same (ads off at launch).
- **All features resolve off until an operator flips gates.** Intended per TA-13.2 / D-14; whoever ships F-PRF-* must include the gate flip in its runbook.
- **UI ACs deferred** to US-020-01 / US-020-04 / F-PRF-002/003 (D-5); the orchestrator should record this in the story close-out.
- Reflection over PlanFeatures: adding a sixth bool to PlanFeatures automatically adds a gate key; `SeededGlobalGates_ExistForEveryPlanFeature` fails until the seed gets that key — intended.
