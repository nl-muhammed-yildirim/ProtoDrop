# F-FND-006 Review — application + infrastructure events + DI

## Findings

[verified] SbEventPublisher (src/wa.infrastructure/Events/SbEventPublisher.cs): topic `core` only (line 22, single use at line 63); MessageId = `envelope.EventId.ToString()` (line 64); PartitionKey forwarded when non-empty (lines 65–66); outbox row written and saved BEFORE publish (lines 44–56) so failure leaves the row unpublished — EC-054-1 no silent drop; IsPublished=true set only after SendMessageAsync succeeds (line 69), second SaveChangesAsync at line 77 is a true no-op when it stayed false (EF sends nothing for an unchanged tracked entity); PUBLISH_FAILED log via `_logger.LogError(ex, "PUBLISH_FAILED eventId=… eventType=…")` at line 74 as the M0 alert path; 10 s timeout via linked CTS + CancelAfter (lines 60–61) with outer ct also honored. Class doc documents TA-4.1.7 at-most-once acceptance.
[verified] SbEventPublisher serialization: single `JsonSerializer.Serialize(envelope)` call, no options (line 41); wire payload and EnvelopeJson column share the exact byte shape; EventType stored via bound converter so plain option-free calls stay valid (line 47). Async hygiene fine — no sync-over-async, all awaits on real async members.
[verified] InMemoryEventPublisher: same `IEventPublisher` contract (`Task<DomainEventRecord> PublishAsync(EventEnvelope, CancellationToken)`); dedup by eventId via `_store.ContainsKey` before insert (lines 29–30) — second publish returns IsPublished=true without a second stored record; per-topic read-back via GetByTopic ordered by StoredAtUtc (lines 38–42); TTL expiry via injectable clock (`Func<DateTimeOffset>` primary ctor, DI ctor with real UtcNow + documented 30-min retention, lines 15/22); byte-exact serialization — identical plain `JsonSerializer.Serialize` as the SB adapter (line 26).
[verified] EventDeduplicator: 15-min window constant (line 15), already-seen within window → true/skip (lines 25–27), post-expiry re-sight records new timestamp and returns false (lines 28–30); purge on insert bounds memory to the sliding 15-minute distinct-eventId span; comparison is time-based (`now - seenAt < Window` for hit, `>= Window` for purge) — no off-by-one at the boundary: exactly-Window elapsed counts as expired in both places consistently. ConcurrentDictionary used correctly (indexer + TryRemove are atomic); doc comment documents consumer idempotency requirement per FR-054-4/AC-054-3.
[verified] Program.cs DI block (lines 21–35): conditional switch on `Wa:ServiceBus:ConnectionString` — empty → InMemoryEventPublisher, set → SbEventPublisher with ILogger<SbEventPublisher> and IDbContextFactory<WaDbContext>; exactly one IEventPublisher registration in either branch; no "is this the fake?" branches anywhere (grep confirms Program.cs is the only consumer-side wiring under src/); DbContextOptions built as a plain singleton via `new DbContextOptionsBuilder<…>().UseSqlServer(…).Options` — established pattern, not AddDbContextOptions.
[verified] AppDbContextFactory: both sync `CreateDbContext()` and async `CreateDbContextAsync(ct)` present (lines 15–18), each constructs a fresh WaDbContext from the injected options; registered as singleton at Program.cs line 26 and resolved by SbEventPublisher via the factory — adapter-owned contexts, no request scope.
[verified] IEventPublisher usage under src/ is exactly: port definition (wa.application/Ports/Events.cs with separate `DomainEventRecord` record type distinct from entity `wa.domain.DomainEvent`), two implementations (SbEventPublisher, InMemoryEventPublisher), Program.cs wiring — nothing else implements or consumes it.
[minor] SbEventPublisher line 62: `_configuration["Wa:ServiceBus:ConnectionString"]!` null-forgives the connection string per publish. The DI path is guarded by Program.cs's `string.IsNullOrEmpty` check, so in practice a missing key can only bite if someone constructs SbEventPublisher manually with an arbitrary IConfiguration — then it NREs mid-publish (after the outbox row was written), not at construction/DI time. Failure mode is loud (logged PUBLISH_FAILED via catch) rather than silent, but fail-fast on construction would be clearer; class doc doesn't explicitly document this assumption.
[minor] SbEventPublisher creates a fresh `ServiceBusClient` per PublishAsync call (line 62). Each publish pays connection-setup cost against the broker; for an outbox publisher invoked from every business command this is real churn at M0 scale. Acceptable under TA-4.1.7's MVP simplification, but worth noting before event volume grows — a cached client or DI-owned sender would be the natural follow-up.
[nit] SbEventPublisher line 47: `JsonSerializer.SerializeToElement(envelope.Type).GetString()!` round-trips the enum through JSON just to obtain its wire name. Correct (bound converter emits e.g. "transfer.created"), but a direct call into EventTypeConverter's wire-name lookup would be more readable and avoid the Element allocation per publish.
[nit] EventDeduplicator is documented as an "LRU" (class doc line 6, comment at line 29) but eviction is TTL-based purge-on-insert, not least-recently-used — reads never touch recency. Functionally equivalent here; the LRU label is a misnomer that could mislead someone expecting read-refresh semantics.
[nit] InMemoryEventPublisher.PublishAsync ignores `cancellationToken` entirely (synchronous body wrapped in Task.FromResult). Fine for a test double, but two concurrent first-time publishes of the same eventId race between ContainsKey and indexer write — both return IsPublished=true with one stored record, which still matches "no double side effect" intent.
[nit] Port doc on IEventPublisher.PublishAsync (wa.application/Ports/Events.cs lines 21–25) describes SB-specific behavior ("writes a DomainEvents row via the EF Core change tracker"), which InMemoryEventPublisher does not do — no outbox rows in the fake. The divergence is intentional and documented inside InMemoryEventPublisher, but readers of the port contract may over-assume equivalence; consider wording the interface doc as "adapter-dependent persistence."

## Verdict
PASS — all slice checks verified (topic/core only, MessageId=eventId dedup identity, outbox-before-publish with no silent drop, 10 s linked-CTS timeout + PUBLISH_FAILED alert path, byte-exact shared serialization in both adapters, eventId dedup + per-topic read-back + injectable-clock TTL in the fake, 15-min windowed deduplicator with correct boundary semantics and bounded memory, clean conditional DI with no fake branches or double registration); findings are all low-impact hardening/nits.
